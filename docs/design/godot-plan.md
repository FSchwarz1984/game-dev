> 状态：**执行中**（2026-10-14）。引擎迁移是用户的决定（E-1），平台与交付已定（W-1…W-3：原生 Windows + 安卓，Artifact 下载页）；本文件里标"待定"的内容决定（小地图解锁方式、美术标杆评审）要先问用户。

> 依据：decision-log 的 E-1、R-1…R-8、F-1…F-3；已批准的 map.md（地图 v2）、systems.md（「移」与五性，含 §1.3"她的身体就是货箱"）、scope-g5.md（G5 范围）、story.md、characters.md。

## 0. 先说清楚的判断

- **用户指出的问题大多出在内容和执行，不在引擎。** 透视混乱、地形不自然、树粗糙、精灵图别扭、台词有 AI 味、性质像货币：换引擎不会自动修好任何一条。Godot 给的是成熟的 2D 工具（TileMap 地形、2D 光照与法线、粒子、动画状态机、UI、音频总线、编辑器级的资源管线），让我们把力气花在美术和设计上，而不是自写引擎。
- **已经批准的设计比做出来的多得多。** 地图 v2 是 830 × 690 米、十七个地点、三层加地下；JS 版只做了峠顶一小块，所以"随便走走就是空气墙"。「移」的身体效果在 systems.md §1.3 早就批准（带着重走得稳、不怕风、压断朽桥；把自己的重给出去就变轻、被风送过断崖），JS 版第一段一条都没做出来。所以 R-2、R-6 的主要修法是**把已批准的设计做足**，不是重新设计。
- **新的要求**（F-1：不分段、不加载、不在画面中间指路、条件解锁的小地图、不要空气墙；F-3：像素立绘、不遮挡文字）写进宪章，全部遵守。

## 1. 技术架构

| 部分 | 做法 |
|---|---|
| 引擎 | Godot 4.7.2 官方版（从 godotengine.org 下载，用 godot-builds 仓库的 SHA512 校验）：编辑器（能在 Xvfb 里跑游戏截图）+ Windows（含 ANGLE、D3D12）、安卓、Linux 导出模板。需要改引擎时再用 `tools/godot/` 里的源码编译脚本。见 `docs/knowledge/10-godot-toolchain.md` |
| 渲染 | 2D；Windows 用 Forward+（2D HDR、辉光、SDF、GPU 粒子碰撞），安卓用 Mobile；原生 480×270，viewport 拉伸、整数倍、expand 填满屏幕；手机只横屏（P-3）。不再做网页版（W-1） |
| 世界 | 一张无缝的大地图，按区域拆成场景，走动中提前加载相邻区域，没有加载画面；边界用悬崖、深谷、河和**遠化之雾**（看得见、剧情里解释过，"远"的东西走不近），不用空气墙 |
| 地形 | 统一 3/4 俯视透视的规则集：地面平铺、崖面一律朝向镜头、台阶按坡向画出踏面和立面、道路贴地；TileMap 地形自动拼接 + 有机形状（多边形 + 纹理边缘）+ 贴花，绝不出现网格感 |
| 光影 | 时间用 CanvasModulate 渐变；灯笼、火、萤火用 PointLight2D + 精灵法线；物体的地面影子用预先画好的柔和影子精灵，随时间**连续**变化，不做逐帧重算（R-7 的跳变来自这里） |
| 角色 | AnimatedSprite2D + 动画状态机；脚本动作结束后一律回到状态机（R-4 的"没有及时切换"） |
| 文字 | 像素中文字体（OFL 授权，例如方舟像素字体或缝合像素字体），对话框按原生像素排版；立绘在自己的框里，**永远不盖住文字**（F-3） |
| 逻辑 | 把 `src/game/field.js` 等纯逻辑移植成 GDScript，保留并移植机器人通关测试 |
| 音频 | JS 版的合成音乐与音效离线渲染成 OGG（用无头浏览器的 OfflineAudioContext），环境录音照用；蜩与铃虫维持合成（A-2） |
| 验证 | 在 Xvfb + Mesa 软件渲染（lavapipe / llvmpipe）里跑游戏，xdotool 发真实键盘、鼠标事件（触摸用鼠标模拟触摸）跑通关机器人；桌面分辨率 + 手机横屏分辨率；安卓包检查清单与体积 |

## 3. 各问题对应的修法

| 编号 | 修法 |
|---|---|
| R-1 透视 | 先写透视规则（崖、台阶、路、桥、水岸各自怎么画），所有素材按规则做；美术标杆阶段专门检查 |
| R-2 地图 | 做足已批准的地图 v2（先做 G5 范围）；没有分段卡和加载；不在画面中间指路，改用看得见的地标、声音和さぢ对看得见的东西的反应；小地图条件解锁（待定） |
| R-3 植被 | 每种树单独设计（松、杉、枫、竹、大楠……），树冠、枝、干一体画，风动用着色器；大楠重做，根、干、冠连成一体，修掉树冠的切口 |
| R-4 精灵图 | 以 GPT 给的三人多角度立绘为参考重做：比例（さぢ不再臃肿）、侧脸（去掉尖嘴）、走路循环、躺卧和趴姿（有体积，さぢ的趴姿不再像断头）；状态机保证动作结束后切回 |
| R-5 剧本 | 重写；人物对大事必须有反应；场景之间连续（树上坠落 → 树根醒来）；样章见评审页 |
| R-6 玩法 | 把 systems.md §1.3 的身体效果全部做出来，参考《流れぬ雛》的手感（见 knowledge/12）：走路速度、风、水、朽桥、浮叶、冰面、发光、潜行……并且在她身上看得见、听得见 |
| R-7 光影 | 影子预先画好、随时间连续变化；任何光影参数都插值，不跳变 |
| R-8 灯火 | 按 v0.1 的点状聚集、倒置沙漏往上流来做（见 knowledge/12 或 14） |
| F-3 立绘 | 12 包立绘像素化（见 knowledge/13）；对话框里立绘有自己的框 |
