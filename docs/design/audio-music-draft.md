## 0. 先说清楚三件事

1. **这里没有声卡，没有人能在这里听。** 上次乌鸦的录音里混进了人声，就是因为没人听过、也没核对内容（G5R3-53 里记的主管过失）。这份提案的做法都按一个原则安排：不靠耳朵也查得出来的问题，我们在交付前自己查掉（响度、削波、咔哒、接缝、重复、内容来源）；只有耳朵能判断的（好不好听、动不动人、像不像电子声、腻不腻），集中在两次关口请你听，每次大约二十分钟。
2. **合成音的长处和短处要一起说。** 长处：每个声音是我们一笔一笔造出来的，里面不会混进人声或别的东西，内容可以逐条说清来历。短处：自然声里那种马上能打动人的复杂性，合成不容易做到；无人深空的声音设计师就不赞成用合成做风雨（研究 §4.10）。v0.1 的风、水、虫鸟你评过"整体不错"，我们以它为底，目标是"画出来的声音"：和我们按像素画渲染的 3D 画面同一个道理，清楚、干净、有设计，而不是去仿一段现场录音。
3. **关于"像旷野之息、异度神剑那样"。** 那是任天堂、Monolith 的专业作曲团队加真人演奏录出来的。你已经定了由我们来写，以 v0.1 的音乐和收音机小曲为起点和水准线（G5R3-63，决定六），音色走合成（G5R3-65）。新写的旋律动不动人，只有你听了才知道，所以关口 1 请你在游戏里听。

## 1. 现在为什么不如 v0.1

不是"合成还是录音"的问题，是变化、层次、空间和调度都没有搬过来（研究 §6.1、§6.2）：

| | v0.1（`legacy/v0.1/src/audio.js`） | 现在的 Godot 版（`godot/core/audio.gd`） |
|---|---|---|
| 每次发声 | 每次重新随机：频率、音量、长度、起播位置都变 | 每种声音只生成一份、缓存起来，每次一模一样 |
| 脚步 | 八种地面各有做法；重了加闷响；草和落叶是一串不规则的小擦声 | 一段滤过的噪声，按地面换个音高 |
| 空间 | 五条总线、两个生成的混响（林间约 2.8 秒，"远"约 5.5 秒），声音有左右 | 没有位置，没有混响 |
| 环境 | 风、叶、竹、溪、瀑布、雨六种底床，加十几种按时辰、地貌、天气发生的生物和事件 | 原来是 20–30 秒的录音循环，现在关了；世界几乎是安静的 |
| 音乐 | 前瞻的音序器：标题、序章、野外（大部分时间安静，按时辰换乐器）、家、紧张、远眺；九个 stinger；遠囃子；收音机 | 没有（`music()` 是空函数） |

## 决定一：声音的风格和边界

**问题**：声音整体按什么标准做；录音在什么条件下还能用。

| 选项 | 内容 |
|---|---|
| **A 合成为主，"画出来的声音"（推荐）** | 风、水、虫鸟、脚步、「移」、界面都由我们合成；追求清楚、干净、有设计感，和画面同一种风格。每个声音都有看得见的声源。录音只作例外：某个声音合成确实做不好，而且那个文件你亲耳听过、同意了，才进包。**乐器采样（钢琴、竖琴等）也是录音**：它们是一个音一个音单独录的，不是野外录音，但我们照样逐个检查（静音段、杂音、类似人声的频谱），关口 1 由你听成品。 |
| B 连乐器采样也不用 | 所有声音和音乐都由合成器产生（音乐只用 v0.1 式的合成音色）。 |
| C 自然声用录音 | G5R3-53 已经否了，只作对照。 |

- **关键变量**：会不会再混进不该有的东西、听不听得出循环；自然感；音乐的质量上限。
- **代价与风险**：合成的风雨可能偏"功能性"，靠风格、空间、调度来补（研究 §6.5）；猫叫、乌鸦叫这类合成难的声音，宁可少而准，不让它常响。
- **什么情况下选别的**：如果你连乐器采样也不放心，选 B；关口 1 就只听合成的一版，不做两种音色的对照（决定六）。

**已定（G5R3-65）：A，而且乐器也合成。** 所有声音和音乐都由我们自己的合成器产生（v0.1 的合成器为底，往上做），不用录音，也不用乐器采样（"不需要非常 acoustic，合成本身就是这种游戏的特殊风格"）。录音的例外通道还在：某个声音合成确实做不好，而且那个文件你亲耳听过、同意了，才进包；到现在没有用过。

## 决定二：音效怎么做（实时合成，还是离线合成多份变奏）

**问题**：v0.1 在浏览器里实时合成（浏览器的音频节点是编译好的原生代码）；Godot 没有这样的节点图，要换做法。

| | **A 离线渲染多份变奏，运行时随机、分层、定位（推荐）** | B 实时合成：用 C++ 写引擎扩展，移植 v0.1 的合成器 | C 实时合成：GDScript + AudioStreamGenerator（现在的路子） |
|---|---|---|---|
| 怎么做 | 先把 v0.1 / JS 版的合成器原样放进无头浏览器的离线音频上下文里渲染（仓库里已有这套工具，`tools/audio/field_browser_check.mjs`；godot-plan 原定的 P5 就是这样），每个声音按不同的随机种子渲染多份，先让 v0.1 的音色原样回来；需要更好的地方再用 Python 写更贵的处理。进 Godot 后用随机池抽取、再抖音高和音量 | 把约 1,800 行的合成器（振荡器、滤波、卷积混响、音序器）改写成 C++，编译成 Windows 的扩展 | 在脚本里逐个样本算 |
| CPU | 很低：只是播放和混音 | 中等；要控制同时的声部 | 高：官方文档说这类用法应该用 C# 或扩展，GDScript 只能降采样率（11 或 22 kHz）将就（研究 §5.3） |
| 质量 | 最高：离线可以用很贵的算法（卷积混响、模态合成、过采样），不受实时预算限制 | 和 v0.1 一样 | 最低：只能很简单 |
| 可控、可查 | 每个文件都能在交付前逐个测量；出问题能定位到哪个文件 | 只能运行时录下来查 | 同左 |
| 变化 | 靠份数和运行时的抖动、分层（份数不够会听出重复，要用统计查） | 每次都不同 | 每次都不同 |
| 工程量（粗估） | 渲染管线 1–2 天；Godot 一侧（总线、声部管理、随机池、3D、区域混响、闪避、环境调度）2–4 天 | 多出一个 C++ 扩展的移植、编译和 Windows 验证，粗估一到两周 | 少，但做不出好声音 |

**推荐 A。** 具体做法：

- **变奏数**：最常听到的最多。脚步每种地面走、跑各 12 份；五性的取、予、放每种 6 份；界面每种 4 份；说话音每人 12 份；环境里的生物和事件每种 8–20 份。运行时"不连续重复"抽取（Godot 的 AudioStreamRandomizer），再抖音高（按声音定，一般不超过 ±1 个半音）、音量（±2 dB）。
- **分层**：一步脚步 = 地面层（草、土、苔、落叶、碎石、石阶、木、树根、浅水、雨后的泥）+ 身体层（重了加闷响，轻了只剩擦声和笠的沙沙，热了带噼啪、踩到湿地嗞一声，冷了带冰碴，带着"音"时像鼓一样共鸣）+ 背着的东西（背负子上的货随步子碰响）。几层各自抽取，组合数相乘。
- **空间**：世界里的声音都有位置（3D 播放器）；远了变闷、混响多，这和王国之泪声音总监说的"远了变朦胧、带回声、融进环境声"是一个方向（研究 §1.5）。听的位置放在她身上、朝向跟镜头，画面左边的东西就在左耳。按区域换混响：林子、屋里、结界里、遠化。
- **混响**：Godot 只有算法混响，没有卷积混响（研究 §5.3）。v0.1 那种"林间空气"的长尾，在离线渲染时直接做进素材；运行时的区域混响只给短的。
- **连续的声音**（风、雨、水、火）：每种渲染 3–4 档强度的长床（3–5 分钟，几层长度互质，比重慢慢游走），按参数交叉；**阵风是单独的事件，和画面上草的风浪用同一份风场**（G5R3-45：风要有随机的频率、方向会变）。
- **调度**：环境里的生物照 v0.1 的规则发生（一天里的时间窗、发生率、同时上限、冷却），雨天少，遠化里少（已有）。鸟在树上、乌鸦在地上、虫在草里：声音从看得见的地方来。
- **闪避**：对话时音乐压低约 8–10 dB、环境约 4 dB（现在是音乐和环境一起压约 3.7 dB，改成分开压）。
- **包体**（粗估）：音效用 Godot 默认的 QOA 压缩导入，长床和音乐用 Ogg；音效加环境约 40–70 MB，音乐另算（曲目表见决定六）。

**什么情况下选别的**：只有在某个声音必须随物理逐个样本地变（比如以后有一件可以弹奏的乐器）时，再为那一个声音加一个小的 C++ 合成器；新手区用不到。

**已定（G5R3-65）：离线渲染和实时合成按具体情况结合**（原话"離線渲染與實施運行視需要與具體情況有機結合"）。每一类按 CPU、质量、可控和与画面、参数的联动来定；现在的分法：

| 类别 | 做法 | 为什么 |
|---|---|---|
| 音乐：地点曲、片段、stinger | 离线渲染 v0.1 的音序器和乐器（筝、三味线的弦模型，铃、钲的加法合成，笛，铺底，生成的卷积混响）；运行时决定何时进、哪一层、多响、怎么交叉 | 卷积混响和弦模型离线做最好，运行时没有代价；曲子是定下来的作品，运行时只需要调度；每个文件都能在交付前测量 |
| 风 | **实时**：长的粉噪声，经 Godot 的高通和低通；截止频率和音量每帧按 v0.1 的阵风随机游走算，再随画面上草地的阵风锋面涨落 | 要跟着天气、风力和画面上的风走（G5R3-45），参数一直在变；运算只是两个滤波器 |
| 树叶、竹、溪、雨 | 离线渲染长循环（每种几档强度，各用各的噪声），运行时按风、雨、林木、离水多远交叉，溪声在溪线上逐段定位 | 里面有很快的沙沙爆发和游走的共振，每秒 60 次的参数更新做不细；离线可以保证每一档都查过：不重复、不啸叫（研究 §12） |
| 生物和天气事件：蝉、鸟、虫、蛙、乌鸦、雷、滴水 | 离线渲染多份变奏；运行时照 v0.1 的时间窗、发生率、同时上限调度，从看得见的地方（树、草、溪、竹、乌鸦本身）发声 | 每一声的音色要逐份检查；调度和位置要跟着世界走 |
| 她和さぢ的脚步、「移」、界面、说话音 | 离线渲染多份变奏；运行时不连续重复地抽取，轻抖音高和音量，叠层（地面、身体、さぢ的铃） | 最常听到，份数最多、边缘最软；按键的同一帧出声（0.1 秒内） |
| 遠囃子、收音机 | 离线渲染同一时间线上的几种远近；运行时合拍地交叉；收音机在世界里定位 | "远"靠卷积混响和滤波；换远近时拍子不能乱 |
| 区域的空间感（结界、屋里） | 实时：Godot 的总线效果 | 跟着她走到哪里；短混响够用 |

GDScript 逐样本合成太慢（研究 §5.3），实时的部分都用 Godot 自带的效果链；需要 C++ 扩展的地方现在没有，真遇到了先提出来。

### 5.3 什么时候安静

- 野外的大部分时间（决定四 C）。
- 遠化的地方：没有音乐，环境声变远、变闷（现在已经有 `Audio.far`），因为那里的东西"失去了性质"。
- 大事之后留 15–30 秒的空，让风和虫说话。
- 下雨时片段变少，雨落在茅草顶、叶子、水面上就是音乐。
- 深夜（零点到四点）几乎只有虫。
- 对话时不停，压低。

### 5.4 怎么过渡

- 片段：一句总是唱完、带着余音结束，不半路切断；过场和战斗才在 1–2 秒内淡出。
- 换地点：等当前的片段唱完；地点曲之间在下一小节交叉 2–4 小节。
- 昼夜：同一位置交叉，约 8 小节；时间被快进时（样章里能按 Q、E 拨时间）先稳住 3 秒再换，不跟着来回跳。
- 遭遇：下一拍进，结束时等到小节末尾带尾巴退，再回到刚才的位置。
- 过场：脚本直接指定，结束后回到之前的状态。
