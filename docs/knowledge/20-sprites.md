# 20 · 角色精灵图（R-4 重做）

日期：2026-10-14。适用：生成器 `tools/art/sprite3d/`，产物 `assets/sprites/`，引擎里的副本 `godot/art/sprites/` 和 `godot/actors/characters.json`。回应用户的 R-4："非常混乱"——脚本动作之后精灵图没有及时切回、走路不自然、平躺和趴着"薄得像只有衣服扔在那里"、さぢ 趴着"像她头断了一样"、侧面的尖嘴"像小老鼠的嘴"、さぢ"像一个很肥胖、很矮小、很臃肿的小矮人"。凡是标【未验证】的都没有实测。

## 0. 一句话

每个角色是一个由几十个有符号距离场（SDF）基本体拼成的小 3D 模型，挂在一副骨骼上，头发、袖子、下摆、带子是模拟的次级运动链；正交相机按游戏的 3/4 俯视角把它渲染成原生像素，再按像素画的规矩风格化（每像素多数表决、色阶、按材质着色的外描边、部件之间的分隔线、左上边缘光、手放的五官像素）。法线贴图来自真实的 3D 法线。

## 1. 为什么换方法

旧的精灵图（`tools/art/` 里的 `tsu_base.py`、`saji.py` 等，已退役，见 §11）是用 ASCII 网格手画部件、像纸偶一样整像素平移拼帧。R-4 的六条里有四条是这个方法的结构问题：

- **躺、趴没有体积**：纸偶只能把站着的部件横过来贴，看不到身体的上表面和侧面的厚度。
- **さぢ 像头断了**：趴着的帧在"梁"的位置留了一道空，空在脖子上，头和身体分开。
- **尖嘴**：侧脸是手画的一个凸起，2 像素就成了鼻尖。
- **走路僵**：腿只是几块预画的部件换位，没有膝盖弯曲、没有脚跟着地和蹬地。

新方法下，这四条都由几何本身保证：任何姿势体积都对（躺、趴、跪、坐、爬），侧脸是椭球的轮廓（没有鼻尖），腿由反向运动学放脚，梁的位置由一个遮挡体决定、永远落在腰胯（§6）。另外两条（比例、脚本动作后切回）见 §2 和 §8。

代价：每一帧是算出来的，所以像素簇不如逐像素手画那样"刻意"。弥补的办法是一套风格化规则（§4）和手放的五官像素（§4.5）。没有逐帧手修。

## 2. 比例：三个头

- **三人同一个比例：约 3 头身**（头高 = 头顶头发到下巴）。实测（站姿，含 1 像素外描边）：
  - つゞみ：头顶 34 像素，戴斗笠到笠尖 40 像素；头 10.5 像素；肩宽 8 像素。
  - しをね：头顶 36 像素（角再高 1–2 像素）；头 10.6 像素。
  - さぢ：头顶 34 像素（含呆毛 35）；头 10.3 像素；肩宽 7、腰宽 5、裙摆 12–13 像素；裙下露出膝盖、白袜、红绳、靴子。旧图 24 像素高、几乎一样宽；现在宽高比约 1 : 2.2。
- **为什么是 3 头**：宪章要求角色 34–40 像素高。3 头时头约 11 像素，正面的脸有 8 像素宽、5 像素高，两只眼睛各 2×3 像素、中间空 3 像素，表情读得出；更大的头（2.5 头）会把身体压成 さぢ 被批评的那种矮胖；更小的头（4 头）脸只剩 1 像素的眼睛。
- **对照世界里的东西**（1 米 = 20 像素）：Q 版小屋的门约 30–34 像素高（JS 版 `props.js` 的门 30 像素），つゞみ 头顶 34、戴笠 40，所以她要微微低头进门，符合"高个子运货人"的形象；祠的檐梁按 0.3 米 × 0.3 米（6 × 6 像素）、2 米长设计（§6）；背负子从腰到头顶以上，立柱尖露出笠沿 3–4 像素（站姿高约 1.2 米 = 24 像素）。
- さぢ 是三人里最小的（座敷童子，孩子），但比例相同，所以她是"小号的少女"，不是"大头娃娃"。

## 3. 视角、方向、像素网格

- **相机**：正交，俯角 20°（`geom.PITCH`），竖直方向按 1/cos20° 拉回，所以**站着的东西一米就是 20 像素高**，地面的深度按 tan20° ≈ 0.36 压缩（和引擎原来画的角色影子椭圆 14×4 一致）。光从屏幕的左上前方来（相机空间 (-0.58, 0.60, 0.55)），所有方向的光都一样（像素画的惯例：形体在哪个方向都是左上亮）。
- **八个方向**：front（向南、朝镜头）、front_right、right、back_right、back、back_left、left、front_left。**左右分别渲染，从不镜像**：三人都不对称（つゞみ 笠上的红带和长长的红腰带尾在她左侧；しをね 的角、两道朱痕、马尾都在她右侧，和用户原画及全部立绘包一致；さぢ 的腰带结在她左侧、呆毛在她右侧）。
- **为什么做斜向**：触屏摇杆和键盘斜按都很常见，只有四向时斜走会侧身滑行；这个管线里多做一个方向只是多渲染一行，没有额外的绘制成本。只给行走类动画（idle / walk / run）做八向；脚本动作按场景需要给四向或两向。
- **斗笠的"作弊"**：笠是圆的，按真实 3D 它在背面会露出巨大的顶面。像素画的惯例是让圆笠在任何方向都是同一个轮廓：笠总是朝镜头后仰 13°（`HAT_TILT`），只有红带随她转。弯腰、低头时笠只跟头部点头的 20%，不然一个 29 像素的草盘会盖住整个人。
- **像素网格**：格子里第 PVX 列覆盖屏幕 u ∈ [−0.5, 0.5)，她的中线穿过枢轴列的正中；第 PVY 行的上沿是地面，鞋底在 PVY−1 行，鞋底下的描边在 PVY 行。引擎把枢轴像素的左上角放在她的地面点上。
- **3D 世界里当广告牌用**（主管 2026-10-14 的新方向）：精灵图仍然是这张网格；法线贴图用平常的约定（x 向右、y 向上、z 朝观众）；每帧带 footL / footR 锚点（脚底着地点）。注意这套图是按 20° 俯角画的；如果 3D 场景用 50–60° 的相机，人物会显得比地面"更正面"。俯角是一个常数，可以按场景的俯角重新渲染，但那时要去掉竖直拉伸、由渲染端决定广告牌的尺寸，并重新检查斗笠的作弊角度【未验证】。

## 4. 渲染与风格化（`tools/art/sprite3d/`）

| 文件 | 作用 |
|---|---|
| `sdf_render.c` + `render.py` | C 写的 SDF 光线投射（正交、每像素 6×6 次采样），按需编译到用户缓存目录（`~/.cache/tengan-sprite3d/`，不进仓库）；输出深度、材质、部件、法线、环境光遮蔽、投影 |
| `geom.py` | 旋转、骨骼、形状（椭球、圆锥体、圆角盒、圆台、圆柱、圆环、带波浪下摆的裙）、两个切平面（第二个固定是地面）、色带（含周期色带：发丝、褶、编织） |
| `humanoid.py` | 共用的 Q 版骨骼、腿的反向运动学、走/跑循环、次级运动链（Verlet，带身体碰撞和地面，段长不变） |
| `model.py` | 模型基类、一帧的渲染（头部亚像素对齐、五官投影、锚点） |
| `style.py` | 风格化：多数表决、色阶、杂点合并、分隔线、左上边缘光、外描边、法线贴图 |
| `face.py` | 五官像素印章（正面、四分之三、侧面；睁、眨、笑眼、闭紧、低垂、张口、喊） |
| `poses.py` | 脚本动作的工具：手臂、IK 放脚、躺/趴/坐的落地、关键帧 |
| `anims.py` | idle / walk / run 的生成与登记 |
| `chars/<人>.py`、`chars/<人>_acts.py` | 三人的模型、调色板、动画登记与脚本动作 |
| `build.py`、`preview.py` | 出图（多进程）、写版式 JSON、×4 接触表与 GIF |

风格化规则（每帧）：

1. **覆盖与材质**：一个像素 36 个采样里命中过半才算实；材质按加权多数（眼睛、金铃、丝带、呆毛权重高，不会被吞掉）。被遮挡体（梁）命中的像素是透明的洞。
2. **色阶**：包裹的兰伯特光 × 投影 × 环境光遮蔽，按每个材质自己的阈值切到 3–4 档。皮肤最低只到中间档（保底亮度）。
3. **清理**：四邻同材质都一样而自己不同的像素跟随邻居；≤2 像素的色阶小岛并入周围。
4. **分隔线**：一个像素在另一个部件后面超过 1.6 个单位（例如袖子盖在身上、头发盖在披肩上），它降到该材质的"线"色阶：重叠读作一条画出来的线，不会糊成一团。
5. **左上边缘光**：上方或左方是空的身体像素亮一档（皮肤和眼睛除外），宪章的"轮廓光"在图上的那一半；另一半（动态补光）在渲染端。
6. **外描边**：轮廓外一圈 1 像素，颜色按相邻材质（与立绘相同的描边色），不用纯黑；遮挡体的洞边不描。
7. **五官**：眼、嘴、腮红、しをね 的朱痕是手放的像素印章，贴在头部骨骼上投影出来的点上，按那一点朝向镜头的程度选印章（正面 2×3 的眼：睫毛、高光、两档虹膜；四分之三时远眼挤成一列；侧面只有近眼一列），被手或笠挡住时不画。**侧脸不画鼻子**：轮廓就是脸的椭球，最多 1 像素的转折。
8. **角色上不做抖动**：没有任何抖动或点状纹理（试过斗笠的稻草编织，读成了噪点，已去掉）。

像素稳定：骨盆高度每帧取整，头部（连同笠）对齐到静止姿势的亚像素相位，所以走路时脸的像素不闪。走路时头只上下 1 像素（落地后下沉一帧）。

## 7. 版式契约（`characters.json`）

```
{ "<人>": {
    "frame": [w, h], "pivot": [x, y], "palette": n, "rider": {view: "behind" | "over"},
    "anims": { "<动画>": { "fps": f, "loop": bool, "views": [...], "sheets": [...], "mirrorLeft": false,
                            "speed": 米/秒（walk、run：1:1 播放时的地速）, "from": 米/秒（run：多快开始跑） } },
    "sheets": { "<表>": { "file": "<人>_<表>", "width": W, "height": H, "cols": c, "rows": r,
        "anims": { "<动画>": { "<方向>": { "row": r, "frames": n, "anchors": [ {名字: [x, y]}, ... 每帧一个 ] } } } } } } }
```

- 一行一个（动画, 方向），第 i 帧在 (i·w, row·h)。每张表配一张同版式的 `_n.png`（法线：RGB = n·0.5+0.5，x 右、y 上、z 朝观众；透明处是 (128,128,255,0)；描边像素的法线朝外）。透明度只有 0 和 255。
- 格子：つゞみ 64×64，枢轴 (32, 58)；さぢ 56×56，枢轴 (28, 50)；しをね 56×60，枢轴 (28, 52)。
- 锚点：像素，相对她的地面点（= 枢轴像素的左上角 = 引擎里节点的原点），x 右、y 下；她的中线在 x = +0.5。每帧都有 `footL`、`footR`（脚底着地点）、`hand`（左手）、`handR`、`head`（头顶上方，给气泡用）；つゞみ 坐姿有 `seat`，背负子有 `loadTop`（さぢ 坐的位置）和 `hook`（右立柱尖，挂灯笼）；さぢ 有 `seat`，被压时有 `hip`（梁的中心）。
- 躺、趴、坐的帧：节点原点是身体在地面上的中心（骨盆下方），正面趴着时是身体最前端。坐在高处（树枝、崖边）时用 `seat` 锚点：`lift = 树枝高 − seat 高`。

## 8. 引擎接入（`godot/actors/`）

- `CharacterLibrary`：认识八个方向和回退顺序（斜向先退到同侧的侧面，再退到正面/背面）；`mirrored()` 只在旧版式的 `side` 视图上镜像。
- `Actor`：`face` 仍是游戏逻辑用的四向；新加的 `dir` 是八向（`Proj.dir8_of`，扇区边缘 10° 滞回，摇杆抖动不闪）；外部改 `face`（场景、出生点）时 `dir` 跟着转。比 `run.from` 快就跑（降到 85% 才回到走），走和跑的播放速度 = 实际地速 / 动画的 `speed`（限制在 0.55–1.7），切换走/跑、转向时保持步相，脚不跳。脚步声在走和跑的着地帧。状态机（R-4 的"脚本动作后切回"）不变，测试照旧覆盖。
- 速度的现实：她的基础速度 3.4 m/s（68 像素/秒），对 34 像素高、腿长 12 像素的 Q 版人物是小跑。走路动画 1:1 时是 1.7–1.9 m/s；在 3.4 m/s 下按 1.7 倍播放，脚还会滑约一成。さぢ 跟随时 3.2 m/s，超过她的 `run.from`（2.9 m/s）所以她跑着跟——腿短的孩子跟大人走，这样反而自然。如果以后把走路速度降到 2 m/s 左右、另设奔跑，走路就完全不滑【建议，未决定】。
- `sync_assets.py` 读 `assets/sprites/characters.json`（旧的 `src/art/characters.data.js` 只在没有新文件时才读），并删掉版式里不再有的旧表。
- `main.gd` 支持 `-- --region=<id>`（只为检查，默认仍是 test）。

## 9. 怎么重建、怎么验证

```sh
python3 -I tools/art/sprite3d/build.py --preview <目录>   # 三人全部，约 2–5 分钟（4 核）；--only saji 只出一人
python3 -I tools/godot/sync_assets.py                      # 复制进 godot/
REIMPORT=1 bash tools/godot/test.sh                         # 换了 PNG 一定要重新导入
bash tools/godot/playtest.sh <目录>                         # 真实输入的试玩
```

同样的输入总是得到字节相同的 PNG（没有随机数；多进程的结果按固定顺序拼）。`--preview` 写每张表的 ×4 接触表（每个动画、每个方向一行）和每个动画的 GIF（所有方向并排）。

本次验证（文件在当次会话的 scratchpad `sprites-r4/`，不进仓库）：接触表与 GIF；旧/新对照；三人八向的头部 ×8 特写；梁下的合成预览；骑乘合成预览；头部上下浮动的数值检查（走 1 像素、跑 2 像素、idle 吸气 1 像素）；Godot 单元测试 68 个；`playtest.sh` 两轮（1280×720 键盘、1200×540 触摸）；八向行走的真实输入截图（xdotool，1280×720 与 1200×540，test 与 home_saddle 区域），核对每个方向的动画名和 さぢ 的跟随。

## 10. 教训

1. **先看"可读"再看"正确"**：3D 正确的东西不一定读得出。斗笠背在背上在 3D 里没错，画面上是一面盖住人的大圆盘；前视的趴姿正确，但头挡住了全身。凡是会被一个大形状挡住的姿势，要么换方向，要么在规则里作弊（笠永远朝镜头后仰）。
2. **薄的东西过不了多数表决**：头带、呆毛、丝带、稻草纹宽度不到半个像素就会消失或变成噪点。要么做成独立的形状、提高权重，要么干脆不画。
3. **切平面要说清楚在哪个坐标系**：第一次把头发的切平面放在形状自己的居中坐标里，刘海整个被切掉，人像秃头。现在一律在骨骼坐标里。
4. **次级运动的地面约束要在约束循环里做**：只在最后把点夹到地面上，段长会缩成零，帧里出现 NaN；现在贴地的段沿地面铺开。
5. **坐、躺时长衣会拖成尾巴**：挂在链上的羽织和袴在坐姿里会沿地面伸出去；坐、跪、躺时改成从腰部落到地面的"堆起来"的形状。
6. **改生成器之前等出图结束**：工作进程是按需导入的，出图中途改了 C 源码，新进程编译了新库、却还拿着旧的 Python 绑定，直接段错误。
7. **头部对齐**：亚像素的身体起伏会让脸的像素一闪一闪；把头部单独对齐到静止姿势的亚像素相位后，八帧的脸逐像素相同。

## 13. 如果以后改用 3D 角色：导出网格有多难

（主管要求的评估，没有做。）

- **静态网格**：同一个 SDF（C 代码现成）在 0.25 像素的网格上采样（一个人约 160×160×120 = 300 万个点，C 里不到一秒），marching cubes（scikit-image 已装）出三角网，再按二次误差简化到 3–8 千面。材质用最近基本体 + 色带算成顶点色或分成子网格。约 1 天。
- **蒙皮与动画**：每个基本体只挂一根骨骼，顶点权重取最近基本体的骨骼，平滑并集的过渡区按 smin 的混合系数分权重；骨骼和每帧的旋转已经在 `poses.py` / `anims.py` 里算好了，写成 glTF 的骨骼动画很直接。头发、袖子、下摆的链要么烘焙成骨骼动画，要么交给运行时的弹簧骨骼。约 2–3 天。
- **难点**：五官现在是 2D 印章，3D 要做成表情贴图集或贴花（1–2 天）；薄的东西（丝带、呆毛、头带）marching cubes 会断，要直接输出成解析网格（圆锥、盒、圆环本来就有公式）；斗笠"永远朝镜头后仰"的作弊在真 3D 里要改成渲染端的处理；像素画的观感要靠渲染端的低分辨率、卡通光照和描边（用户的纸人原型就是这样做的）。
- 结论：技术上不难，主要成本在五官和薄部件，估计 1 周可以得到能动的 glTF；画面品质要和渲染管线一起调。
