# 08 · 2D 像素渲染器与家园地图：做法与教训

日期：2026-10-14。来源：本项目 `src/gfx/`、`src/env/` 的实现与无头 Chromium 截图对比（截图在会话 scratchpad，未入库）；v0.1 的 `legacy/v0.1/src/render.js`、`pixel.js`。关于 Eastward 的说法是对成品画面的观察，没有官方技术资料佐证，标为【观察】。

## 1. 管线（已实现）

- **投影**：3/4 斜投影，正交。屏幕 = (X, Y − Z)，深度 D = Y + Z（越大越近）。1 m = 20 px，x 东、z 南、y 上。原生 480×270 左右，整数倍放大；视野随屏幕比例扩展，不拉伸、不加黑边（390×844 → 236×510 ×5）。
- **地面是烘焙的**：地形按“台地 + 立面”建模（每级高度一个多边形），CPU 逐列从北往南画（画家算法），台地顶面按材质逐像素画，高度下降处画立面（野面石垣、土坎、自然岩、台阶踢面）。结果打包成 256² 的块纹理（反照率 + 材质/标志，法线 + 16 位高度）。
- **延迟光照**：G-buffer（反照率+材质 / 世界法线+自发光 / 遠化·湿·类别·投影者 ID）+ 深度。光照全屏一遍：太阳（阴影图）、天空与地面反弹、≤32 个点光、雾与光柱、遠化、角色保护光。
- **阴影图**：地形高度场代理只保留背光面（cullFace BACK）；精灵用“转向太阳的卡片”投影；用投影者 ID 排除自阴影；树冠在地面上的光斑是慢速、软边的噪声，不随风抖。
- **角色保护**（不得退化）：角色的可见度在脚下用 12 点平均（不逐像素取阴影），有保底亮度、天空补光、左上轮廓光；角色身上不做分档、不做抖动、不受摇曳的叶影。v0.1 的闪烁正是这三条原因。

## 2. 这次踩过的坑（按代价排序）

1. **满屏棋盘格抖动**。光照分 4 档再用 Bayer 抖动、地面和精灵的色阶边界也用 0.5 幅度的 Bayer 抖动，放大 3 倍后整屏是“纱窗”。做法：光照完全平滑（不分档、不抖动）；绘制用的 Bayer 幅度全局降到 0.4（`core.js DITHER_K`），色阶边界只剩 1–2 像素的点。【观察】Eastward 的地面和植物几乎看不到棋盘格，靠的是成簇的形状。
2. **草地是噪声，不是草**。逐像素噪声挑色阶，看起来是迷彩。改成“草丛”：11×7 的抖动网格，每格一个半椭圆的草丛，顶部是参差的草叶尖，左上亮、脚下一条暗线；每个像素取覆盖它的最前（屏幕上最靠下）的草丛，草丛自然互相遮挡。再用一个慢变化的场分出“茂盛”和“矮”的区域，避免一块均匀的花纹。苔藓同一套逻辑，圆、无草叶。
3. **树冠：一堆球 vs 一个整体**。用户否决过“体素球树”。单个大椭圆又平又假。现在 `paint.js crown()`：一个偏暗的核心（缝里露出来的就是它）+ 三排互相重叠的鼓包（顶排用嫩叶色），每个鼓包 84% 按整个树冠的形体受光、16% 按自己；纹理用“每个叶簇一个平的色调偏移”（`blobK`），色阶边界碎成叶簇形，而不是每格都有完整明暗（那样像鱼鳞/瓦片）。**画布要比树冠大 40%**：鼓包会超出名义宽度，画布小了两侧被切成直边（踩过）。
4. **斜投影里，垂直落差就是一堵墙**。14 m 的崖在屏幕上是 280 px 高的墙，比整个画面还高；崖下的树梢在可见范围之外。暗示“地势落下去”的做法：崖下做成每级 3 m 的陡坡台阶，每级种两排树，**树高选到树梢比崖顶高约 2 m**（`home.js SLOPES` 的 `level`）：这样正好盖住上一级的立面和地面，又不会遮住崖上的路和观景台。远近感用“脚下地面有多深”的雾（光照里按模糊高度图取雾），而不是按树叶本身的高度。
5. **九十九折从正上方看是横条**。东西向的台地 + 平行的路 = 一条条横带。改成每段路斜穿台地、在短台阶处折返，石垣只砌在路贴边和台阶落脚处，其余是土坎；台地上种竹叶草、蕨、杜鹃、芒。仍然只有在拐弯处（台阶）一眼读出“之”字形，见 §4。
6. **石垣像砖墙**。规则的行和错缝就是砖。改成拉长的 Voronoi（宽于高、越靠下越大），每块石头左上倒角受光、缝里偶尔塞苔藓（野面积み）。
7. **根像触手**。尖头、完全露出、长条的根就是触手/爪。改成：在主干处大幅外扩、约一半长度处钻入地下（盖一小堆土和苔藓），再冒出一两段低矮的拱。

## 3. 遠化（Far）的样子（`shaders.js farLook` + 精灵顶点）

- 颜色：向冷的浅蓝灰收，亮度抬高、对比压缩，但保留形状（混合 82%，保留 30% 原色相的明度结构）；完全照搬颜色会变成一块白色剪影，读不出是什么。
- “退后一步”：底部略缩、向后推，玩家越近推得越多；轮廓上有慢速的闪烁和整行的微小横移。**不透明**，照样挡路、照样投影。
- 地面：4 px 一格的遠化遮罩，`R.paintFar({x, z, rx, rz, amount, angle, ragged})` 画椭圆。

## 4. 已知不足（如实）

- 树的种类少（杉、黑松、枫、山茶、杜鹃），远看会重复；杉树仍偏“圣诞树”。【观察】Eastward 的树是手绘的大块形体加少量精确的高光，程序化做不到那个水准。
- “之”字形只在拐弯处可读；“path” 镜头是拐弯处的构图。
- 烘焙（`createHomeMap()` 全部）在 Node 里约 4.3 s（地形绘制约 2.5 s，布局与精灵绘制约 1.8 s），浏览器标签页里 4–5 s，手机会更慢。热点：逐列绘制 1.0 s、草丛 0.5 s、树冠 0.4 s、精灵 AO 0.2 s。建议放进 Web Worker 在标题画面期间烘焙，或把纯静态部分缓存。
- 北边的铁塔只有走到东北台地北缘、镜头看到“空”的区域时才出现：3/4 视角里远处只能在地图边缘露出来。

## 5. 验证方法

- `node tools/env/build.mjs` 构建测试页；`node tools/env/shots.mjs [名字…]` 截图（1280×720、1920×1080、390×844、844×390），按帧数等待；`node tools/env/perf.mjs` 测各档帧开销（SwiftShader，只看相对值）。
- `node tools/env/sheet.mjs flora|props|camphor` 在 Node 里出精灵对照表（只有反照率，不含动态光）。

## 6. 第二轮美术（同日，主管审稿后）：回到 v0.1 的语言

主管审稿结论：渲染管线保留，环境美术不过关（并排看，正午和观景台不如 v0.1）。改法和结果：

- **植物改用 v0.1 的生成器**（`src/env/flora1.js`，移植自 `legacy/v0.1/src/art_flora.js`）：叶簇画法 `clump()`（错位网格上的小圆顶，每格只取几档色调之一，下半部压暗，法线来自格子的圆顶高度，所以动态光会把每一簇的左上照亮）；杉树是叶簇堆成的密塔，不是“圣诞树”；层叠圆盘树（绿色读作松，红色是红枫）；竹、蕨、熊笹、葛、芒、山百合、紫阳花、露草、蘑菇；新增彼岸花。大楠的树冠块也改用同一套：暗色内腔 + 分层叶团，上沿受光。
- **树按树丛摆放**：每丛混合几个树种、几种尺寸，丛与丛之间留空地；坡下的树按“树梢比崖顶高约 2 米”选树种，位置抖动，并随机留缺口。
- **地面改回 v0.1 的 terrainFS 画法**（`groundmat.js grass`）：大块草地色斑 → 几像素的草丛三档色调 → 只在亮处的稀疏 1×2 草叶高光、只在暗处的缝隙 → 干枯、橄榄色斑块 → 三叶草与野花按遮罩出现。材质边界在像素尺度上抖开（`terrain.js`：只在边界附近，沿细噪声偏移取样）。
  - **教训**：三叶草按固定网格放会出现点阵，必须在格内抖动并降低密度。
  - **教训**：逐像素函数里不要建小数组，否则 GC 会多占几百毫秒。
- **九十九折**：三段斜路，分别在三层台地上，转弯处是短石阶；台地边缘沿路斜着走、宽窄不一。可达性检查：`src/env/reach.js` + `tools/env/reach.mjs`，从入口做 BFS。每次 `tools/env/build.mjs` 都会跑，任何地点不可达就构建失败。
- **调色**（`tod.js`，以 v0.1 的表为底）：
  - 黄昏：琥珀色主光、偏紫蓝的暗部、整体更暗。
  - 夜：蓝色月光，绿色在合成时偏向冷蓝并去饱和，不再发绿；灯笼是暖橙色。
  - 正午：绿色在合成时偏向橄榄色，有薄雾和光束。
  - 第一天早晨：苍白、安静。
- **灯笼**：纸面自发光只给纸本身（逐像素），不再给整个精灵；颜色琥珀而不发白；泛光在夜里调低；光晕改成平滑的。灯笼的形状和杆子都看得清。
- **不阻塞的烘焙**：`createHomeMapAsync({ onProgress })`。整条烘焙是一串 generator，每一步都很小（逐列绘制、逐行填充、逐个精灵），驱动程序每 20 ms 让出一次。实测（无头 Chromium）：烘焙约 5.4 s，期间约 320 帧，最长帧间隔 33–50 ms（偶发 GC）。

与 v0.1 的并排对比（我的判断）：黄昏和夜晚明显好过 v0.1（氛围、可读性）；正午与 free1 大致持平——形体和光更清楚，但单帧里的树种和密度仍不如 free1。

## 7. 大楠下的空地：拼布式草地（主管审稿 #2）

问题：鞍部空地在早晨是一大片均匀的橄榄绿草坪，只有稀疏的草丛，看起来像毛毡。改法（`groundmat.js clearing()`，布局在 `home.js`）：

- **几种草地拼在一起**，每块约 2–4 米：潮湿深色、普通、矮而晒褪色，另有密集的三叶草。三种草地用同一个画法，草丛反差压到 60%，彼此只差一小档明度和色相。交界用 v0.1 的有序抖动过渡，不用硬边。
  - 第一次试的版本是“迷彩”：几种画法反差各不相同，交界是硬边，大块苔藓平涂。所以变化要靠明度和色相上的小台阶，纹理的反差要统一。
- **树根周围是一圈苔藓**：用最近点（Worley）生成软垫状的苔藓，两种格子尺寸由慢变的噪声选择，所以看不出平铺；只有部分格子之间有暗缝。外缘长出草叶，边界随噪声伸缩。
  - 每个格子都画暗缝时，看起来像鹅卵石路；苔藓软垫画成扁椭圆时，会排成横向短线，又回到了“短线墙纸”。
- **地面贴花（没有碰撞）**：落下的樟叶（2 像素，四种颜色）和细枝，靠近树根最密，往外渐稀；还有几块半埋的石头，左上受光，下沿有影子，阴面有苔藓，树根附近多一些。
- **她每天走的路被踩秃**：三条路分别是门前到祠、门到树根下她放东西的地方、树根到祠。每条路是两层区域：外层是踩出斑块的带（pa 196），里层是踩实的芯（pa 236）。`clearing()` 根据 pa 计算露土的程度，露出的土比院子的土略暗、略暖，旁边的草也略暗。没有她来回走的理由的地方，不出现露土。
- **花**：露草在树根和小屋旁的潮湿处，女郎花（新画的精灵 `ominaeshi0..2`）开在空地有阳光的边缘。花都是小精灵，没有碰撞器。它们按自己的区域取样，用单独的随机数生成器，所以地图其他地方的摆放不变。
  - 实测：精灵位置变化的只有空地外约 40 丛草；碰撞器、对象、可走格子数与改动前完全一致。原因是苔藓区和草地的材质变了，主随机序列在几处短暂错开，随后又对齐。
- 结果（早晨、黄昏、手机横屏并排）：不再是毛毡；人物、背篓、祠、梁、木架都还清楚。早晨的雾光下拼布反差偏小，黄昏更明显。
