# 静态立绘的演出：漫符、立绘动作、对话框与文字（2026-10-16，G5R3-13；第 5–8 节 AVG 研究，G5R3-19）

用户否了立绘的眨眼和说话动嘴（G5R3-13），要求立绘保持静态，演出改用漫画符号和画面、对话框的动作，"按专业游戏美术参考动态漫画设计去丰富完善"。这一份是设计之前的研究：专业游戏和动态漫画怎么让静态立绘"演"，我们取什么、不取什么。设计提案在 `docs/design/dialogue-staging.md`（草案，待审）。

## 1. 结论先说

1. **静态立绘靠"拍子"演，不靠连续的动。** 每个拍子是一个短促、清楚的强调：一次弹跳、一下横抖、一个漫符弹出、一次闪白。拍子之间立绘静止，字照常读。
   - 逆转裁判的制作人说，早期作品帧数少，"异议あり！"的气泡只有一两种变化，反而得到了"别处得不到的速度感和利落感"；3D 重制时他们刻意打乱节奏、插入停顿来还原这种感觉。这一说法来自转述，原始采访未核实。
   - 动态漫画也是同一个路子：把画格放大成整屏，再加声音和少量动作。维基百科特别指出视觉小说"只偶尔"在画面里做局部动作。
2. **词汇要少而固定。** 星露谷的事件脚本只有几个演出词：
   - `emote`：头顶的小图标，有问号、怒、惊叹、心、睡、伤心、开心、×、"……"、音符、脸红；
   - `jump`：跳，带强度；
   - `shake`：抖，以毫秒计；
   - `screenFlash`：闪白，带强度。
   Ren'Py 的标准转场里，`hpunch`、`vpunch` 是横、竖震屏各四分之一秒，"闪光"是快速变白再回来。一个小而固定的词表，写剧本的人记得住，玩家也学得会。
3. **文字特效用"包住一段字"的标记。** Celeste 的对话文件在台词里直接写 `{~}波浪{/~}`、`{*}抖{/*}`、`{!}冲击{/!}`、`{big}大{/big}`、`{>> 0.5}慢速{>>}`、`{0.5}`（停半秒）；每句开头用 `[角色 左/右 表情]` 换立绘。Undertale 按说话人和情绪，偶尔给字的基线加波浪或抖动，并用打字速度当"嗓音"。我们的剧本标记照这个思路做，用中文写。
4. **漫符的意思和位置是约定俗成的，照约定用**（维基百科"漫画符号"条）：
   - 汗滴在额头或眉边（尴尬、无奈、困惑、慌）；
   - 怒筋是头上部一个空心的十字，多跳几下表示更生气；
   - 竖线阴影在头上或眼下（难堪、疲惫、恐惧）；
   - 红晕是脸颊的斜线；
   - 嘴角的虎牙或猫嘴表示调皮；
   - 头顶的"……"表示无话可说；
   - 人物周围粗黑的线表示气得、吓得发抖；
   - 集中线、速度线强调动作和情绪（Clip Studio 手册）。
   符号贴在约定的位置，不压五官。
5. **可读性和舒适度是硬约束，不是可选项。**
   - XAG 117 的要求：
     - 动的文字对阅读慢的人、对晕动敏感的人都是障碍；
     - 镜头震动应当避免，或者提供关闭选项；
     - 反复的左右、上下晃动，除非是玩法核心，也应当避免。
   - WCAG 2.3.1：任何一秒内闪烁不超过三次，或者闪烁面积和亮度变化低于阈值。
   - 所以我们要有"减少晃动"开关，闪白一句最多一次，抖动只给短短一段字。

## 3. 由此定下的约束（写设计时照这些）

- **只用整像素平移**：原生 640×360 下以 1 像素为单位，在 1080p 下就是 3 屏幕像素。不旋转、不缩放、不模糊，像素格永远完整；这也是宪章"不做小数倍缩放"的延伸。
- **幅度和时长**：
  - 抖、震：1–3 原生像素，约 0.25 秒（Ren'Py 的量级）。
  - 跳：2 原生像素。
  - 闪白：一句最多一次，0.1–0.2 秒内回落；任何一秒内不超过三次（WCAG 2.3.1）。
- **字永远读得清**：
  - 对话框和正文只在重拍时整体平移一下，平时不动。
  - 抖字只给几个字；打完字后就停，不让一整句一直抖（XAG 117）。
  - 没有更小的像素字号，Fusion Pixel 12px 已是最小，所以低声用变淡，不用缩小。
  - 大字用整数倍（24px），保持像素字形。
- **立绘永远不挡字（F-3）**：卡片的平移幅度要留在卡片和正文之间的 8 像素空隙里。
- **漫符**：
  - 每个拍子最多一个新漫符。
  - 贴在约定的位置：额头、太阳穴、头顶、脸颊，头旁边的卡片底色上；不压五官。
  - 第四版已经画进立绘的符号（惊讶的"！"、大喊的"！！"、生气的怒筋、怀疑的问号、思考的泡泡、嘟嘴的"哼"、疲惫的汗）保持不动；新漫符是独立的小图，风格和它们一致：深色描边、同一套色。
- **"减少晃动"开关**：
  - 关掉一切位移和闪白：滑入、弹、抖、震、抖字、波浪字。
  - 漫符照常出现，但没有动画（直接显示最后一帧）。
  - 大字、变淡、停顿保留：它们不是动作。

## 5. AVG、galgame 积累的演出手法（2026-10-16，G5R3-19）

用户批准词表时说："我覺得你可以參照更多的AVG， galgame，這種文字遊戲積累多年的表現形式去積極吸取他們的經驗當然不要照般也不要生搬硬套。"这一节按主题整理文字游戏的成熟做法。依据分两种：引擎的标签文档（吉里吉里 KAG3、TyranoScript、Ren'Py），记录的是这个类型几十年里约定成俗的手段和默认参数；制作者的访谈（TYPE-MOON《魔法使いの夜》、Key 的麻枝准、逆转裁判的本地化总监）。ゆずソフト、5pb./MAGES 的科学 ADV、弹丸论破的对话演出，这次没有找到可引用的一手说明，只作印象，不作依据（见 §8）。

### 5.1 立绘的登场、退场、位置

- 引擎默认值是"慢慢出来"：
  - TyranoScript 的 `[chara_show]` 默认用 1000 毫秒淡入，`[chara_hide]` 默认 1000 毫秒淡出，`[chara_move]` 默认 600 毫秒移动。
  - Ren'Py 的 `moveinleft` 一类转场让新立绘从画面边上滑进来，用 0.5 秒；`moveout…` 同样 0.5 秒滑出去；`move` 让换了位置的立绘 0.5 秒滑到新位置。
- 《魔法使いの夜》的演出、脚本つくりものじ说，"传统的演出表现不好'まほよ'的世界观"，所以"尽量从传统的表现里出来"。采访者概括的传统文法是"背景上立绘正面站着，一来一回地对话"；つくりものじ说这种"约定"在他看来"成了把玩家卷进故事的障碍"。他不做"FPS 式的第一人称演出"，而是配合奈须的第三人称文体。这部作品的事件 CG 几乎都是立绘组合出来的；美术こやまひろかず把平视的素材重新组合，做出"仿佛镜头在动"的演出。重要场面先画分镜，日常场面边做边找"这样接起来顺"的办法。

我们取的：对话框里一张卡片、整卡片平移的做法不变（D1），它本来就不是"正面立绘并排对话"。引擎默认的 0.5–1 秒淡入在像素画、短拍子的节奏里太慢，我们保留 0.2 秒的滑入。

### 5.2 表情什么时候换

- Ren'Py 允许在说话语句里直接写表情（`e happy "……"` 等于先 `show eileen happy` 再说话），`@` 后面的表情只在这一句有效；要在一句话中间换表情，用 `extend`：前一句末尾加 `{nw}` 自动收尾，换表情，再接着说同一句。
- 麻枝准谈《Heaven Burns Red》：他在文字游戏里养成的规矩是"这样的台词配这样的立绘表情""这样的场面放这样的音乐"；他监修时把"随着每一下点击切换的表情，全部自己重新分配一遍"。
- こやまひろかず谈《魔法使いの夜》："脚本做下去发现表情不合，事后追加表情的情况相当多"。

我们取的：表情跟着这一句的情绪走，不提前；情绪在句子中间转折时，就在转折处换（新标记 `[脸:…]`，见 §6）。换表情是瞬间切换，不做交叉淡化：两张像素图叠化会产生调色板外的中间色。

### 5.3 暗转与场面转换

- TyranoScript 的 `[mask]` 就叫"暗转"：默认 1000 毫秒盖黑，`[mask_off]` 1000 毫秒揭开。
- Ren'Py 的 `fade`：0.5 秒变黑，再 0.5 秒变成新画面；`Fade(out, hold, in, color)` 可以在黑里停一会儿，也可以换成别的颜色。
- 吉里吉里 KAG3 的 `[trans]` 有三种方式：`crossfade`（叠化）、`universal`（用一张灰度"规则图"决定画面从哪里先变，配 `vague` 控制边缘的模糊宽度）、`scroll`（推入）。
- 奈须きのこ说《魔法使いの夜》用四季的变化表现"世界正在被改写"：场面转换本身也能讲故事。

### 5.4 背景的震动与推拉

- KAG3 的 `[quake]` 横、竖振幅默认各 10 像素；时长可以用毫秒，也可以用"字数"（`timemode=delay`），也就是让震动的长短跟着读者设定的文字速度走。
- TyranoScript 的 `[quake]` 参数表里的初始值：震 5 次，每次 300 毫秒，竖向振幅 10 像素，横向 0；`[quake2]` 是 1000 毫秒内的一次大震（默认竖向 200 像素）；`[camera]` 能把画面放大、平移到某处，默认 1000 毫秒。
- Ren'Py 的 `hpunch`、`vpunch` 各震四分之一秒（§2 已用）。
- 《魔法使いの夜》：青子的光束原定 4 道，因为第一发的演出做得太华丽，最后改成 8 道，还加了远景的拉开（つくりものじ、奈须、こやま）。奈须同时举了反例：草十郎的眼睛要是"突然唰地发光"，"就让人泄气了"。

我们取的：震只震画面、只用整像素（D5）；推拉里的"拉近"要放大画面，违反"不做小数倍缩放"，不取；整像素的平移可以（见 §7 提案 6）。

### 5.5 文字窗口的显示与隐藏

- Ren'Py 的 `window auto` 默认在换场景（`scene`）、调用画面、无标题的选项之前把对话窗口收起，在说话前放出来；`window show` / `window hide` 可以带转场。
- KAG3 的消息层用 `[position]`、`[layopt]` 的 `visible` 显示、隐藏。

我们取的：暗转和换场景的时候不留对话框。现在的导演代码已经是这样：对话框只在 `say()` 期间存在，`fade` 和 `card` 不带它。这条写进规则（§6）。

### 5.6 文字演出：速度、停顿、强调、注音

- 速度：
  - KAG3 的 `[delay speed=user]` 是默认值，也就是"玩家在系统菜单里设的文字速度"；`nowait` 一下全出。
  - Ren'Py 的 `{cps=20}` 定一段字的速度，`{cps=*2}` 按当前速度加倍；`{fast}` 让它之前的字立刻出来。
- 停顿：
  - KAG3 的 `[l]` 是"行末等点击"，`[p]` 是"翻页等点击"。
  - Ren'Py 的 `{w}` 在句子中间等点击，`{w=0.5}` 等半秒或等点击；`{p}` 换段并等点击；`{nw}` 这句打完自己收走。
- 强调：
  - Ren'Py 有 `{size}` 改字号、`{alpha}` 改透明度（我们的 `[大]`、`[轻]` 同类）。
  - 弹丸论破的"不间断议论"里，可以反驳的"弱点"用黄色标出来：强调的字同时是可操作的东西。
  - 中文横排的着重号（实心小圆点）**放在字的下面**，日文横排则放在上面（W3C《中文排版需求》5.3.1）。
- 注音：KAG3 的 `[ruby]` 给下一个字注音；Ren'Py 的 `{rb}…{/rb}{rt}…{/rt}` 把注音居中放在一段字上方。大逆转裁判的日文原版里，难字和时代用语上方用小号注音标出现代读法（例如「洋食堂」注"レストラン"），保留时代感，同时"让文字对玩家保持好读"；英文版参照了这个做法（本地化总监 Janet Hsu）。
- 速度和声音连在一起：Janet Hsu 说英文版字多，有些地方把打字加快了；加快以后打字音的尾巴被切掉，所以另做了新的打字音。

### 5.7 没有配音时怎么做"间"

- Janet Hsu（Polygon 采访，Nintendo Everything 转引）：大逆转裁判的日文版"用一套专门的脚本语言精心做出说话的感觉"，控制的有每一句的显示速度、文字和音效在哪里停、停多久，"甚至为了喜剧效果控制动画播放的速度"；英文版"重现'被念出来'的感觉、让喜剧的时机恰到好处"是一项巨大的工作。
- 麻枝准：他写不了台词以外的叙述（地の文），所以很难做出"间"；《Heaven Burns Red》里靠制作方的丰富演出补上了，"某种意义上比做文字游戏时还顺"。
- 奈须きのこ：他不要好莱坞式的"每五分钟一个看点"，坚持"以缓慢的时间为基础去造一个世界"。
- 引擎层面，"间"的工具就是 §5.6 的那几样：
  - 定时停顿：`{w=0.5}`、我们的 `[停0.5]`；
  - 等点击：`[l]`、`{w}`，让玩家自己按出这一拍；
  - 换段：`[p]`、`{p}`；
  - 变速：`{cps}`、我们的 `[慢]`、`[快]`。

### 5.8 演出和音效同步

- 奈须きのこ：真正下了功夫的场面，"音乐、音效全部都控制着"，时机和音量都调过。
- 麻枝准：他以"零点几秒"为单位要求"这里放这段音乐"；他以前自己写脚本（调文字和图片切换时机的简易语言），知道技术上能做到哪一步。
- 逆转裁判：音效什么时候响、响多久写在脚本里（Janet Hsu，见 §5.7）。
- KAG3 的震动时长可以按字数算（§5.4）：演出跟着读者的阅读节奏走，而不是固定的秒数。

## 6. 结论一：直接进词表（这次已接进游戏）

1. **`[等]`：句中等按键。** 打到这里停下，出现翻页箭头；玩家按一下，同一句在同一个框里接着打。依据：KAG3 的 `[l]`、Ren'Py 的 `{w}`（§5.6），这个类型最基本的"间"（§5.7）：让玩家自己按出这一拍，比定时停顿更像对话。打字中按一下，字只补到下一个 `[等]`，不越过它。立绘页的演示里有一句：小鹊"……`[等]`顺路。"
2. **`[脸:表情]`：句中换表情。** 打到这里换成另一张表情，带这张表情的默认拍子和漫符（`[静]` 时不带）。瞬间切换，不叠化（§5.2）。依据：Ren'Py 的 `extend`、说话语句里的表情属性；麻枝准按每一下点击分配表情。演示里有一句：さぢ"……`[停0.4]`（换成开怀）第三个坛子里的梅干。"
3. **写法规则（不改代码）：**
   - 表情跟着这一句的情绪走；情绪在句中转折就用 `[脸:]`，不要为了"提前铺垫"而提前换（§5.2）。
   - 暗转、字幕卡、换场景之前先把对话说完，对话框不出现在暗转里（§5.5）。导演代码现在就是这样。
   - 重拍（框抖 + 大字，震屏，闪白）只给一场戏最重的一句；日常戏宁可慢，不追求密集的看点（§5.4、§5.7 奈须的两段话）。
   - 停顿优先用标点自带的停顿和 `[停]`；`[等]` 会让玩家多按一下，一场戏用一两次，留给笑点和揭晓之前。

## 7. 结论二：等用户看过实机再定（提案）

以下都会改变玩家看到、听到或操作的东西，按协议先提案，等用户在 Windows 版里看过现在的演出再决定。

1. **拍子配音效。**
   - 问题：框抖、震屏、闪白、漫符弹出要不要有声音。
   - 依据：逆转裁判在脚本里控制音效的时机；奈须、麻枝都以零点几秒为单位对音乐和音效（§5.8）。
   - 推荐：配。一小套短促的真实录音（拍桌、木头的"咚"、风铃一类），每个拍子一种，音量低于说话的打字音；"减少晃动"打开时声音照常。
   - 代价：要找、改素材；宪章规定合成音只用于音乐和法术，所以这些音效要用录音。
   - 选别的情况：用户在实机里觉得现在的无声更安静、更合适。
2. **文字速度设置。**
   - 依据：KAG3 的默认速度就是"玩家在系统里设的速度"（§5.6）。
   - 推荐：设置里加"文字速度"：慢 / 标准（现在的每秒 30 字）/ 快 / 立刻。拍子跟着字走，速度变了，拍子的时机也跟着变。
3. **隐藏对话框看画面。** 文字游戏的惯例是按一个键（PC 上常用鼠标右键）把窗口收起来看画面。推荐：等有了值得停下来看的画面（眺望、远景）再加。
4. **着重号 `[重]`。**
   - 做法：中文横排在字下面加实心小点（§5.6，W3C《中文排版需求》）。
   - 风险：行距只有 16 像素，点要放进两行之间约 4 像素的空隙，要先做预览，确认不挤、不像下划线。
5. **注音（ルビ）。**
   - 用处：人名、地名的读法，例如"百々"读"もも"。
   - 风险：注音要比正文小，Fusion Pixel 12px 已是我们在用的最小字号。需要先核实 Fusion Pixel 更小的版本（8px、10px）有没有覆盖要用的字。
6. **对话里的镜头平移。**
   - 依据：《魔法使いの夜》把素材重新组合，做出"镜头在动"的感觉；TyranoScript 的 `[camera]`（§5.1、§5.4）。
   - 推荐：只做整像素的慢平移，例如说到远处的东西时镜头移过去。不做拉近：拉近要放大画面，违反"不做小数倍缩放"。
7. **一张卡片还是两张。** ADV 的惯例是两三个立绘左右站位，对话框里只放名字；我们是对话框里一张卡片，只放说话人。
   - 推荐：维持一张。つくりものじ认为正面立绘一来一回的对话妨碍投入（§5.1）。
   - 可选：在框右端给听话的人放一张小一号、压暗的卡片。
8. **自动播放、已读快进。** 文字游戏的标准功能，剧本长了以后需要。推荐：第一段完整成品时一起加。
9. **暗转的方式。**
   - 现在：渐黑（Cinema 的 fade）。
   - 依据：KAG3 的 `universal` 转场用灰度规则图控制画面从哪里先变（§5.3）。
   - 可以做一种和浮世绘版画呼应的转场，例如按"色版"一层层揭开，和遠化"褪版"的视觉规则（G5R3-18）同源。这是美术方向，要单独提案。
