# 17 · 地形烘焙管线：矢量布局 → 3/4 斜投影像素地面（R-1 的实现）

日期：2026-10-14。适用：`tools/terrain/`（生成器）、`godot/world/regions/home_saddle/`（产物）。规则依据 [15-perspective-rules.md](15-perspective-rules.md)；地面模型契约见 [16-godot-architecture.md](16-godot-architecture.md) §5。截图、对照图在会话 scratchpad（`terrain-final/`），未入库。标【未验证】的没有实测。

## 0. 结论

- **透视问题从结构上解决了。** 地形写成矢量数据（每层平台一个多边形、台阶对象、道路折线、水），烘焙时按斜投影逐像素画：平台顶面按俯视画，朝南的崖面按正视画、高度恰好是高差 × 20 像素，东西向的崖收成 1–2 像素的侧边，北面看不见。台阶嵌进崖里，底端落在下层、顶端接上层，两侧有阶梯状的边石（南面看得见）和石垣；路只是平台上的材质，换层只走台阶或缓坡（自动检查：0 处违规；缓坡 1:6.8）。
- **基准场景**：峠顶约 120 × 100 米，大楠、小屋（0.5 米石垣台）、祠（0.5 米台）、无缘墓所在的下一层（石垣背后）、向东三折的旧路到道祖神和东口、南缘的眺望岩（双层崖）、北面三段石阶通往北口、西北岩壁下的泉。全部可走通：用核心自己的 `RegionData` 读产物，从出生点沿路下三段台阶到东口、上三段台阶到北口都不被挡；直接走下南缘会被挡（2.5 米崖）。
- **画面**：低饱和橄榄绿与赭色（Godot 正午草地 L\* 37–40、C\* 18–19，v0.1 正午 41 / 20；第一版烘焙 54 / 36 被主管否掉）；崖面是由 CC0 照片扫描切出来的层状岩板；影子随太阳高度连续变化，不会跳变。
- **还差风来之国很远**（§8）：这一版只有地面。和 JS 第一段并排看，透视和结构明显更好；但 JS 画面里树、草本、光斑、暖色调色带来的丰富感，地面本身给不了，要等植被、建筑、物件和调色。

## 1. 方法（`tools/terrain/`）

一条命令：`python3 tools/terrain/bake.py tools/terrain/layouts/home_saddle.json --godot`，约 2 分钟（4 核）。

1. **布局 → 世界栅格**（`layout.py`，20 像素/米）：
   - 平台：闭合样条（向心 Catmull-Rom，不打结）+ 有机边缘：中尺度起伏（扭曲的 fbm，波长几米）、偶尔的豁口与凸岩、像素级的草皮团块；起伏幅度沿边线变化（有的段平顺、有的段破碎）。只在边线附近算噪声，所以快。
   - 台阶、缓坡附近噪声衰减到 0，崖线在那里平直、和台阶对齐。
   - 按顺序叠：先画低处，再叠高处。
2. **顶面上色**（`mat_top.py`）：在世界坐标里画，每个像素是（色阶编号，色调档）。先大形（几米的湿冷 / 橄榄 / 晒褪的草地，边界碎成团块），再草丛团（聚成团、团与团之间留空地），再稀疏的字形（草簇、野花、石子、崖脚落石）。
3. **斜投影**（`painter.py`）：每个世界像素是一个"顶面候选"，每处向南的落差生成一列"立面候选"；每个屏幕像素取深度 D = z + h 最大的那个（离镜头最近），这正是斜投影的画家顺序。
4. **立面上色**（`mat_face.py`）：纹理坐标是（x，绝对高度），所以岩层在整条崖上保持水平、任意高度的崖取同一块岩石。崖顶有翻下来的草皮团，崖脚有下层的草挡住立面底边。
5. **光照数据**（`lighting.py`）：每个像素朝太阳方位的地形地平线仰角，和天空可见度（AO）。
6. **导出**（`export.py`）：见 §5。

## 2. 几何：15 号规则怎么落地

| 规则 | 实现 |
|---|---|
| 平台 0.5 米一级、崖面朝南 | 高度取自布局；立面像素数 = 高差 × 20，由投影保证 |
| 东西向的崖只给 1–2 像素 | 屏幕上左右相邻的顶面高差 ≥ 0.3 米时画侧边：朝西（迎光）亮，朝东暗；高差 > 1 米时 2 像素 |
| 台阶嵌进崖里 | 台阶对象：踏面 0.4 米、踢面 = 高差/级数（0.25 米左右）；两侧边石比踏面高 0.15 米、逐级下降（南面可见）；顶上一对石柱；上端平台 0.8 米、下端前庭 0.8 米；左右各 1–1.8 米把崖线拉直并换成野面积み石垣 |
| 路贴在平台上 | 路只改材质；车辙、中间的拱、边上草压过来的暗线、路缘草舌、路边被踩短的草（成片，不成带） |
| 缓坡 ≤ 1:3 | 缓坡对象按两端高度线性插值，超过 1:3 报警；投影时 1 像素的"台阶"按坡面画 |
| 有机轮廓 | 样条 + 多尺度噪声 + 衰减；崖顶草皮翻边（0–6 像素，成团）；崖脚落石、草挡住底边 |

## 3. 材质与调色

- **色阶**（`palette.py`）：全部在 CIELAB 里生成。每条 8 档：中段色度最高、两端降到一半多；暗部色相转向青蓝（冷影）、亮部转向黄赭（暖光）。时间段不重画，交给光照。
- **对照 v0.1**（`skimage` 测 CIELAB，草地像素 = 色相 95–160°）：

| 画面 | L\* | C\* | 色相 |
|---|---|---|---|
| v0.1 正午（截图） | 40.7 | 20.0 | 140 |
| v0.1 夕光 | 26.7 | 16.1 | 105 |
| JS 第一段早晨（被否） | 47.4 | 16.4 | 131 |
| 本管线第一版烘焙 r1（主管否：荧光绿） | 53.9 | 36.1 | 138 |
| 现在：Godot 正午 | 37–40 | 18–19 | 123–127 |

- **照片扫描只当形状来源**（Poly Haven，CC0）：`dark_rock_02` 的高度图放大到 6 米一块、横向拉长 1.4 倍，叠上一道锯齿状的"层理"，再用分水岭切成岩板；每块按自己的朝向取一档底色，上沿亮一档、左沿亮半档、下沿暗一档；只有凹进去的分界才画成黑缝。`rock_wall_10` 切成野面积み的石块，`dry_river_pebbles` 给碎石坡和土坎里的石头。缓存在 `tools/terrain/data/atlas_*.npz`，烘焙不用联网。
- **踩过的坑**：
  1. 色度：第一版亮部色度近 36，就是 G3 被否的"荧光绿"。现在以 v0.1 的测量值为目标。
  2. 崖面像黑带：太阳从西北来时朝南的崖全在阴影里。改成西南偏西（§4）。
  3. 崖面竖条纹（"梳子"）：立面像素的地平线从崖脚算起，边线的像素级锯齿让相邻列交替进阴影。改成从立面前方 4 像素起算。
  4. 迷彩：几套斑块系统叠在一起、草丛团的平均明度比空地暗，读起来就是迷彩。只留大而软的斑块，并让草团"不比空地暗"（团间暗缝按密度出现，团体整体抬亮）。
  5. 苔藓像规则的格子：Worley 格子太均匀。改成三种尺寸、扭曲格点、只在成团处有垫状，其余是平的苔地。
  6. 林床像迷彩：苔藓只长在土丘上，丘间露土，不再是绿斑贴在褐地上。
  7. 石阶像黑梯子：踢面颜色和踏面同一种石头，只靠光照拉开；边石压低到 0.15 米。

## 4. 光照契约（R-7：影子连续）

- **太阳方位固定**，朝向（x 东、z 南）= (−0.92, 0.38)：从左上、偏西南来。这样朝南的崖面受光（主管要求崖面读成"被照亮的岩石"，只有崖脚和右侧可以暗），朝东的一侧和东边的影子变暗，物理上自洽。**代价**：地面上的投影朝右、略偏上（东北东），不是 15 号规则字面上的"右下"；高处物体（树冠）的影子相对物体本身仍在右下方。若要严格"右下"，方位改成西北，代价是朝南崖面全在阴影里（第一版的黑带）。这是一个要用户拍板的取舍【未提案】。
- **地平线贴图**：每个像素存"朝太阳方向看过去，地形挡住的最高仰角"。运行时 `vis = smoothstep(仰角 − 2.5°, 仰角 + 2.5°, 太阳高度)`：太阳高度连续变，影子长短就连续变，任何时刻都不会跳。
- **Godot 里的分工**（`tools/terrain/godot/terrain.gdshader`）：CanvasModulate = 环境光（天空色）；一盏 DirectionalLight2D 只提供太阳的颜色和强度，方向由 shader 用世界向量算；地形的 `light()` 只让太阳乘上 `vis`，灯笼（PointLight2D）照常通过法线贴图起作用。`fragment()` 里用天空可见度和法线的朝上分量调环境光，并给墙面加一点地面反光。
- **时间段预设**（预览用，最终由核心的时间系统决定）：早晨仰角 24°、正午 58°、黄昏 15°（暖金，崖面被低角度阳光照亮）、夜 40°（月光，冷蓝）。数值在 `tengan_terrain/preview.py`。
- **角色**：烘焙里有世界坐标的 `masks/sun.png`，角色按脚下取样决定自己在不在阴影里；样例里的占位角色还有亮度下限（角色保护）。真正的角色光照归核心。

## 5. 数据格式（产物）

`godot/world/regions/home_saddle/`：

| 文件 | 内容 |
|---|---|
| `region.json` | 核心契约的键（`id`、`size_m`、`origin_m`、`cell_m` 0.25、`max_step_m` 0.3、`logic`、`art`、`art_offset_px`、`spawn`、`companion`、`shots`、`entities`、`zones`）+ `terrain`（块列表、编码说明、太阳方位、datum）+ `markers`（大楠、小屋、祠、墓、道祖神、眺望岩、泉、出口的位置与占地，给其它生成器）+ `stairs` |
| `logic.png` | 核心的地面模型：每 0.25 米一格，R×256+G = 高度（厘米，含 datum），B = 核心材质编号（0 空、1 草、2 土、3 石、4 台阶、5 浅水、6 深水、7 崖/墙） |
| `ground.png` | 整片反照率，给现在只认单张美术图的 `world.gd` 用（无光照） |
| `terrain/cXX_YY_*.png` | 512 × 512 的屏幕块，每块四张：`albedo`（RGBA）、`normal`（Godot 2D 法线：R 屏右、G 屏上、B 出屏）、`light`（R 地平线仰角 ×255/90、G 天空可见度、B 材质码：顶面编号或 32 + 立面样式）、`depth`（R×256+G = round(D×2)+8192，D = (z+h)×20，越大越近；B = round(h×4)） |
| `terrain.gdshader` | 地形 shader（同 tools/terrain/godot） |
| `walk_regions.json` | 在高差 > 0.3 米处切开的可走区域多边形（米），给导航/碰撞用 |
| `markers.json` | 同 region.json 的 markers 与 stairs |

- **datum**：布局里的高度以鞍部为 0（便于设计），导出时统一加 `datum_m`（这里 10 米），保证核心的无符号厘米编码不为负。所有导出的高度、位置都已含 datum。
- **坐标**：游戏像素 X = x × 20，Y = (z − h) × 20；块的 `pos_px` 就是它左上角的游戏像素。
- `tools/terrain/out/<name>/`（不入库）另有世界栅格的 `masks/height.png`（厘米 + 32768）、`masks/material.png`（我们的材质编号、可走、标志位）、`masks/sun.png`，和四个时间段的整图预览。

## 6. 核心怎么接

1. **现在就能走**：`RegionData.load_dir("res://world/regions/home_saddle")` 直接读 `logic.png`；`world.gd` 照常把 `ground.png` 放在 `art_offset_px`。试玩机器人可以在这张地图上走。
2. **要有光照时**：用 `tools/terrain/godot/terrain_chunks.gd`（`TerrainChunks.load_region(dir, def)`，每块一个 Sprite2D + CanvasTexture + ShaderMaterial；`set_sun(仰角)`）替换单张 `ground.png`；它用 `load()` 读导入过的纹理，导出包里也能用。已在核心工程的副本里实测（正午 58° 与 20° 两种太阳）。
3. **流式加载**：块在屏幕坐标里切（512 像素），按镜头可见矩形加减即可；地图大了以后每个区域一套块。
4. **遮挡**【未实现】：角色站在高台北边时应该被高台挡住。`depth` 块就是为这个准备的：角色像素的深度 = (z+h)×20，地形像素深度更大就藏起来（或挖透视孔）。现在样例里角色总画在地形上面，只有台阶、平台南侧这些位置是对的。
5. 导入设置：块和 `ground.png` 是无损纹理、无 mipmap；`logic.png` 用 `image` 导入器（产物里已有 `.import`，Godot 第一次打开会补全）。

## 7. 验证（都可重跑）

- Godot 4.7.2、Mobile 渲染器、Xvfb + lavapipe：七个视点 × 早 / 午 / 昏 / 夜，加四张 ×3 特写（石阶、崖角、路的拐弯、平台边缘），手机横屏 600 × 270 视口一组。占位角色站在平台、台阶上，夜里有灯笼。
- 可走性：核心 `RegionData` 实测两条路线（东下三段台阶、北上三段台阶）不被挡、越过南缘被挡；Python 按同一规则 BFS，所有地点可达。
- 道路检查：沿每条路的中线，高差 > 0.3 米只出现在台阶或缓坡上（0 处违规）。
- 网格检查：反照率行列功率谱在 20 像素周期处与相邻频率持平（比值 0.99 / 0.98），6–60 像素内最强的峰只有局部中位数的 1.1 倍。
- 并排对照 JS 第一段的同类画面（石阶与崖、土坎与路、草地、夜里的墓）。

## 8. 已知不足（如实）

1. **离风来之国还远。** 地面是程序生成的规则画法，细看是"整齐的自然"：草簇、花、石子是同一套字形反复出现，崖面岩板的形状来自少数几块扫描（6 米一个周期，长崖上细看能找到重复）。风来之国的地面靠大量手放的物件和植物，这里没有。
2. **光影的方位取舍**（§4）没有提案，现在按主管的"崖面受光"做。
3. **遮挡没做**（§6.4）：角色走到高台北侧时不会被挡住。
4. **眺望岩顶**的浮雕感偏"软"，有些暗色裂纹是虚线状；**泉**只是静水（浅边、岸的倒影带、几道闪光），没有水流动画和出水口。
5. **夜**偏暗、**雨天**没做（宪章检查表要求雨天截图）。
6. 小屋石台和祠台读起来仍有点"规整"，要等建筑放上去再看。
7. 只有一张基准地图；大地图要按区域切开、相邻区域的接缝（崖线、路、datum）还没有设计。
8. 这些截图都是软件渲染，没在真机上看过。
