# 05 v0.1 复盘：为什么得了 0 分

v0.1（2026-10-13）在 `legacy/v0.1/`。用户的评价是 0 分。以下是用户指出的问题，以及查出来的原因。

## 用户原话里的问题（2026-10-14）

- 上手几乎不能玩；移动端优化差，操作反馈不明确。
- 交互内容集中的地方要反复微调站位才能触发想要的操作。
- 没有旷野之息那样的隐性自然引导；机制反馈模糊，很多根本没有反馈。
- 设计质量不如旧 demo（《流れぬ雛》）：用户要的是"像法术一样的性质转移，一个玩法衍生出很多东西"。
- 没有小怪，没有星露谷式的开荒种田、模拟经营。
- 流程：全程没有征求意见，擅自做决定。
- 画面不美观、混乱：开局人物站在阴影里像素不停闪，看不清；可交互物没有像素游戏应有的易识别性；场景混乱，很多东西认不出（铁道粗糙抽象）；透视混乱、缺乏立体感和层次感；素材重复度高，尤其是植被；大树、鸟居比例撑不起"德库树下被笼罩的家"的感觉。
- 大树变成银色幽灵跟着玩家走，看起来是 bug。
- 小溪边刮大风时有很怪、不和谐的声音。
- 认可的部分：剧情演出的电影动画感；声音整体不错。

## 查明的原因

- **幽灵树：** 设计效果，不是代码错误。远化后的大楠被设成始终保持 86% 的镜头视差（`GHOSTS.add(..., { par: .86 })`），想表达"走不近"。开局没有任何铺垫，渲染又像贴图错误。教训：神秘的规则必须先被看见、被说明。
- **角色闪烁：** 角色与地面共用逐像素光照：风中摇动的树冠阴影（阴影贴图里随风摆的叶片投影）、阈值极窄的硬边漏光斑（`smoothstep(.62,.66,n)`）、四档量化 + 有序抖动（`band()`）、同样抖动的体积光束；每个低分辨率像素的变化在屏幕上是 3×3 色块。对照实验显示静止时画面每帧仍有 13–20% 的像素变化，来源不止一个。教训：角色必须有独立的稳定光照。
- **怪声：** 最可能是"大风中树干吱呀响"事件（`evCreak`：14–36 Hz 锯齿波过 200–300 Hz、Q=12 的带通，触发率 ∝ 风速²），听起来像电子嗡鸣。另一个可能是独木桥（远化点）附近淡入的遠囃子（故意调高约 6 音分，加音高摇晃和随风变化的音量）。教训：自然环境声用真实录音；神秘的声音要有可见声源。
- **站位：** 每个动作各自找目标（`target(r, filter)`），半径 18–30 世界像素，朝向只有前、后、侧三档，朝向加权只有 8 像素，没有滞回，交互优先级（献 > 调查 > 拾取）会把其他选项藏起来，目标只在 HUD 提示里显示，不在世界里高亮。
- **核心玩法被砍窄：** 把旧 demo 的四性（重熱光音，彼此和水、火、风、敌人连锁）收成单一的"重"。名义上是扬弃，实际上是抽象否定。
- **流程：** 把用户给的方向当成了全部决定的授权。

## 值得保留的东西

- 序章的电影式演出：镜头、停顿、字幕卡、远景镜头、遠囃子的设定。
- 合成音频引擎（`legacy/v0.1/src/audio.js`）：总线、生成的混响、祭囃子、按时辰的虫鸣鸟叫、主题旋律"九音上行、第十拍全体静默"。修掉 `evCreak` 并给遠囃子设可见声源后可以复用。
- 构建脚本的纯 ASCII 输出（`legacy/v0.1/tools/build.mjs`）：防止 Artifact 宿主把中日文读成乱码。
- 无头测试方法（见 `playtest-capture` 技能）。


## 追记：G3 灰盒的教训（2026-10-14）

用户试玩 G3 灰盒后的反馈与决定（decision-log P-1、P-2）：

1. **"技能全部使用不出来"**。原因：界面层 `.ui` 设了 `pointer-events: none`（为了让摇杆能触到画布），技能键盘作为它的子元素继承了 `none`，手机上一个键都按不动。我当时的"手机验证"只量了按钮的位置和大小，试玩脚本又直接调用游戏函数，绕过了触摸层，于是把没验证过的东西报成了"已验证"。
   - 规则：验证操作必须用真实输入（`tools/inputcheck.mjs`）；修 bug 前先用旧代码复现失败。
2. **"画面水平完全不如 v0.1 那种感觉"**。灰盒的占位美术（荧光绿、平涂、体素球树）让用户无法判断最终效果，甚至判断为倒退。
   - 规则：**不向用户展示任何非最终品质的画面。** 内部可以灰盒，交付只交成品。
3. 美术方向的修正：最终画面 = v0.1 的氛围 + HD-2D 的立体感，并修掉 v0.1 被批评的问题（见 CLAUDE.md "美术底线"）。
