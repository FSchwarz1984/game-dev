# 18 · 植被：程序生成的像素树木与草本（tools/flora → godot/art/flora）

日期：2026-10-14。适用：`tools/flora/`（生成器）、`godot/art/flora/`（产物，Godot 直接用）。规则依据 [15-perspective-rules.md](15-perspective-rules.md)（§0 光照约定：受光与投影分开）、工程约定 [16-godot-architecture.md](16-godot-architecture.md)（Y 排序、地面点、法线贴图），地形契约 [17-terrain-pipeline.md](17-terrain-pipeline.md)。截图与对照图在会话 scratchpad（`flora-bench/shots/final/`、`flora-sheets/`），未入库。标【未验证】的没有实测。**这些是内部素材，用户还没看过。**

## 0. 结论

- **64 株，17 类**：大楠 ×2、杉 ×5、赤松 ×5、枫（绿 ×3、转红 ×3、红 ×2）、山毛榉 ×4（3 株是苔藓林型）、柿 ×3、竹丛 ×3、紫阳花 ×4、杜鹃 ×4、杂灌木 ×4、芒 ×5、蕨 ×5、彼岸花 ×4、露草 ×4、女郎花 ×4。每株是一个 Godot 场景，放进 `World.things` 就能用；反照率 + 法线贴图，树冠有风动、有透视孔（她走到后面时开洞），有随太阳高度连续变化的投影。
- **一条命令重建**：`python3 tools/flora/build.py`（约 30 秒，4 核机器），结果确定（同样的种子出同样的像素）。
- **针对用户 R-3 的批评**：大楠现在是一个整体——板根从树干里长出、表面根半埋入土；八根主枝从树干分出、伸进各自托着的叶团，树冠下沿能看见枝干；树冠轮廓由叶簇组成，没有直线切边和接缝。和被否的 JS 版（树干一张图、14 个树冠团块各自摆放）比，结构上明显更好。
- **还不够好的地方**（§7）：所有阔叶树的树冠是同一种"叶簇团"画法，大面积看像花椰菜；草本和小花很小，在 ×1 下读得出但不精彩；树影是贴在地上的乘法图层，互相重叠会变深、过崖不会折。

## 1. 一条命令与工具

```sh
python3 tools/flora/build.py                       # 全部 → godot/art/flora（res://art/flora）
python3 tools/flora/build.py --only cedar,fern     # 只重建几种（其余不动）
python3 tools/flora/build.py --out DIR --res res://art/flora   # 输出到别处
python3 tools/flora/bench/make_bench.py <dir>      # 植被试验台（独立的小 Godot 工程，结构同核心）
bash tools/flora/bench/run_bench.sh <dir> -- --layout=saddle --preset=dusk --shot=a.png --full=b.png
python3 tools/flora/compare.py --js <JS 精灵目录> --pistachio <iso_pines.png> --out <dir>   # 对照图
```

- 全量构建会删掉目录里已不再生成的植物和文件；保留下来的 PNG 的 `.import` 一并保留（Godot 按文件名认，不按内容）。新增文件后要让 Godot 导入一次（打开编辑器，或 `REIMPORT=1 bash tools/godot/test.sh`），类名 `FloraPlant`、`FloraField` 才会进全局类表。
- 试验台三种布局：`row`（每种一株排成行）、`glade`（大楠空地的构图）、`saddle`（**真实地形**：读 `godot/world/regions/home_saddle` 的底图、`logic.png` 的高度与材质、`markers.json` 的大楠、小屋、祠、墓、泉，把植物放在它们该在的地方，只放在草地或土上、脚下平整的位置）。四个时间段预设用地形的时间表（早 24°、午 58°、黄昏 15°、夜 40°）。
- 需要 numpy、scipy、Pillow（容器里已有）。

## 2. 方法（`tools/flora/flora/`）

1. **建模在自然空间（米）**：树干、枝、根是沿路径扫出的管子（`raster.tube`，半径可随角度调制：板根、树皮棱）；叶团是椭球，表面覆盖小叶簇（`plant.mass`，叶簇半径 0.1–0.27 米，带"波纹"凸起，边缘不规则）；草叶、花瓣、羽穗是二维笔画（宽度 ≤ 0.55 像素时退化为 1 像素线）。
2. **画面空间**：3/4 斜投影（屏幕 y = 20(z − h)）。圆形物体自身的南北纵深压到 0.42（`KZ`）——注连绳是浅弧、树干正面朝向镜头、树冠底面看得见，这是像素画的通行画法；法线仍按自然形状算。**例外**：躺在地上的根不压缩（`kz_cs=1`），否则根会被压成细棍。
3. **逐像素 z 缓冲光栅化**（numpy），然后着色：叶簇按簇取平色（不逐像素渐变），法线混合包络与叶团、穿过其它叶团的自遮光（带噪声斑驳）、天光、地面反光、叶团顶边 2 像素高光、叶团之间的投影；树冠里面有一块暗色"内腔"，叶团之间的空隙露出它和穿过它的枝。色阶按 `src/env/core.js` 的 `ramp()` 移植：暗部偏冷、亮部偏暖。
4. **光（15 号 §0 的约定）**：
   - **受光**按屏幕空间：主光来自左上、略在前面（相机坐标 (−0.55, 0.60, 0.58)）。这个方向烘进反照率（植物自己的明暗），Godot 里由 DirectionalLight2D 的屏幕方向给出（**rotation −42.5°、height 0.42** 正好是这个向量）。
   - **投影**按西北的太阳：朝太阳的地面方向 `SUN_TOWARD_XZ = (−0.92, −0.38)`（西北偏西），影子一律落在右下方；以 40° 仰角烘焙，运行时按太阳仰角连续伸缩、滑动。**这个方位必须和地形的地平线贴图一致**：地形集成时改 `toward_xz` 时，同时改 `flora/core.py` 的 `SUN_TOWARD_XZ` 并重建。
5. **法线贴图分面**：每个叶簇（每段树皮）一块平均法线，Godot 的灯照上去是一块一块亮，和画出来的明暗一致，不会出现逐像素的光滑高光。
6. **风数据**：每个叶团、每束草、每枝竹叶是一个"摆动组"，按深度排序编号；组的柔度（离树干越远越软）烘进数据图。
7. **投影**：树冠的影子用光线穿过所有叶团的透射率算（不是一个圆），三档（全影、半影、光斑），去掉孤立像素；树干的影子是线；接触阴影是贴地 0.06–0.45 米内的部分投在地上再模糊，三档。

## 3. 产物格式（`godot/art/flora/`）

| 文件 | 内容 |
|---|---|
| `flora_plant.gd` | 场景根脚本 `FloraPlant`：`place(x, z, h)`、`lift(h)`、`set_sun_vis(v)`、`block_circles()` |
| `flora_field.gd` | `FloraField`：所有植物共用的运行时状态（她的位置、风、太阳仰角与影子颜色），静态函数 |
| `shaders/foliage.gdshader` | 所有画出来的层：风动、透视孔、受光（CC0，自写） |
| `shaders/flora_shadow.gdshader` | 投影与接触阴影（乘法混合，CC0，自写） |
| `plants/<种>/<名>/` | `<名>.tscn`、`meta.json`、各层 PNG：`trunk` / `crown` / `ground`（反照率）、`*_n`（法线：R 屏右、G 屏上、B 出屏）、`*_d`（数据）、`shadow` |
| `catalog.json` | 每株：种、类别（tree / shrub / herb）、场景路径、各层偏移与尺寸、树冠排序点、阻挡圆、占地多边形 |

- **数据图 `*_d.png`**：R = 摆动组编号（0 = 不动：木、树冠内腔），G = 柔度，B 的第 7 位 = 叶团内壳（叶子被风吹开时露出的暗色），第 6 位 = 能挡住人（透视孔只在这里开），A = 覆盖。导入用无损、无 mipmap（Godot 默认即是）。
- **投影图 `shadow.png`**：R = 树冠影，G = 树干影，B = 接触阴影（不随太阳动），A = 三者最大。
- **场景结构**（根节点原点 = 树脚在地面上的点）：

| 节点 | 说明 |
|---|---|
| 根 `Node2D`（`y_sort_enabled`，`flora_plant.gd`） | 元数据：`flora_species`、`flora_kind`、`flora_layout`（tree = 干 + 冠；body = 一个整体）、`flora_crown_sort_px`、`flora_block`、`flora_collision` |
| `ShadowContact`、`Shadow` | z_index −9，贴地，乘法；后者是投影（树冠 + 树干取较深者，同一棵树的两种影子不叠深） |
| `Ground` | z_index −8，躺在地上的根，永远画在人下面 |
| `Trunk` | 在树脚排序；大楠的树干也能开透视孔 |
| `Crown` | 位置 = (0, `crown_sort_px`)：在树冠投到地上的南缘排序，站在树冠下的人先画、树冠后画。灌木和草本的整株也叫 `Crown`，在脚下排序 |

所有材质都是场景的子资源，同一场景的所有实例共用：`FloraField` 每个材质设一次，就覆盖这个品种的所有实例。

## 4. 游戏里怎么接（核心还没接，集成时照做）

1. **放置**：`var p := (load(catalog[name].scene) as PackedScene).instantiate() as FloraPlant`，`world.things.add_child(p)`，`p.place(x, z, field.ground_height(x, z))`。和角色一样：节点在地面点 `Proj.sort_px(x, z)` 排序，画面按高度抬起（16 号 §3）；投影和地上的根跟着抬（它们不参与排序）。
2. **阻挡**：`p.block_circles()` 给出以树脚为原点的圆（x、z、半径，米）：大树干按画出来的扁椭圆脚印排一串圆，细树干一个圆，灌木一个略小于树丛的圆，草本没有（她从草里走过去）。核心的 `Mover` 只认圆形物体，可以给每个圆加一个不可选中的 field 物体；或者烘进区域的 `logic.png`。由主管决定。
3. **每帧**（她移动之后）：`FloraField.set_player(Proj.to_px(P.x, P.z, P.h), Proj.sort_px(P.x, P.z).y)`。前者定透视孔的位置（她画出来的脚），后者判断她在不在这一层的后面（地面点）。
4. **时间段**：世界视口里一盏 DirectionalLight2D（rotation −42.5°、height 0.42；颜色 × 能量 = 太阳色）、CanvasModulate = 天空色（环境光），再调 `FloraField.set_sun(仰角, 太阳色, 天空色)`；地形 shader 用同一个仰角。影子的颜色按地形的光照模型算成"开阔平地上 天空 /（天空 + 太阳 × N·L）"，所以树影和崖影一样深。夜里有灯笼时传 `strength` 约 0.5（见 §7）。核心现在没有 DirectionalLight2D（`tod()` 只是调色占位），那样植物显示烘焙的明暗 × 调色，也成立，只是平一些。
5. **风**：`FloraField.set_wind(0..2)`（0 无风，1 平常，2 大风）。每个摆动组按整像素平移（0 或 ±1；shader 支持 ±2，现在没有植物用），从不在像素之间插值，所以不会闪；同一棵树的阵风同步，不同树相位不同。
6. **在崖影里**：`p.set_sun_vis(v)`（0..1，实例参数），按地形 `masks/sun.png` 在树脚取样决定。只减主光，不动环境光。
7. **透视孔**：只对"她"一个人（一个位置）。她的地面点在这一层的排序点以北、而且这一层在她胸口、腰、头三处真的盖住她时，在她胸口开一个台阶状透明度的椭圆孔（13 × 19 像素，剩 25%）。

## 5. 验证（怎么验的）

- **试验台**（Xvfb + Mobile 渲染器 + 软件 Vulkan，世界视口与核心相同：480×270、2D HDR、像素对齐、最近邻、辉光，×3 显示）：`row`、`glade`、`saddle` 三种布局，早、午、黄昏、夜四个时间段，×3 局部和整片原生截图都看过。
- **风不闪**：大楠树冠在风力 1.5 下连录 8 帧，相邻帧之间变化的原生像素里 97.9% 能由"整块左右平移 1–2 像素"解释，其余是叶团分开时露出的内壳色；没有半透明、没有插值。
- **透视孔**：树干后、树冠下各截一次（试验台和核心工程里都看了）：她清楚可见，孔边是台阶状的像素。
- **主光方向**：关掉环境光只留主光渲染一次，树冠左上亮、右下暗，树干左亮右暗：DirectionalLight2D 的 rotation −42.5°、height 0.42 确实是"左上、略在前"。
- **核心工程**：把 `godot/` 整个复制到 scratchpad，导入，在测试区域里用 `FloraPlant.place` 放了 10 株（包括 1.5 米高台上的一株赤松），她在出生点、在大楠树干后、在大楠树冠下各截一张：排序、抬高、透视孔、投影都对；脚本和 shader 没有报错；61 个单元测试照常通过。退出时的"4 个对象泄漏"是核心的环境声（`wind.ogg`）留下的，不放植物时也有。
- **对照图**（×3 / ×2 同像素密度）：新树 vs 被否的 JS 精灵 vs CC0 素材（pistachio 针叶树、ansimuz 阔叶树），以及 JS 第一段截图 vs 新的 Godot 截图并排。

## 6. 和 JS 版、CC0 素材比（如实）

- **大楠**：结构明显更好（一个整体、枝伸进叶团、根是半埋的隆起，不再是"树干一张图 + 一堆团块"）。JS 的树干本身有性格（粗、苔、枝很夸张），新的树干更自然，夸张不如它。树冠大面积看像花椰菜。
- **杉**：比 JS 的"圆锥团"细致得多；和 pistachio 比，新的更圆润（杉的叶确实成团），pistachio 的针叶更尖、更有"针叶树"的锐利感。
- **赤松、枫**：沿用 v0.1 被用户认可的"层叠枝盘"画法，比 JS 大、细节多；转红的枫是叶团边缘先红，近看像"边上沾了红"。
- **山毛榉、柿**：读得出是树，柿子挂在外侧；树冠仍偏"一团云"。
- **竹、灌木、紫阳花**：明显好于 JS。
- **草本**（芒、蕨、彼岸花、露草、女郎花）：改过一轮后和 JS 大致持平：蕨和芒好一些，彼岸花的"蜘蛛状"花丝在 ×1 下不明显。
- **放在真实地形上**（`saddle`）：大楠的影子在正午盖住空地中央到祠，黄昏斜扫过整片空地；杉林、竹、紫阳花、路边的花草各在其位，画面是成立的。但和 JS 第一段并排，新画面更暗、更空：这一半是地面（地形本身还平）和没有调色，一半是植被还少（只放了 92 株）。

## 7. 已知不足

1. **树冠质感单一**：所有阔叶树（大楠、山毛榉、柿、枫）都是"叶团上覆盖小叶簇"，种与种之间靠形状和颜色区分，叶簇质感差不多；大面积看像花椰菜。没做逐种的叶形（大楠的光亮小叶、山毛榉的细碎、柿的大叶）。
2. **影子是贴图**：重叠的影子相乘会变深（两棵树的影子交叠处）；影子画在植物自己的地面高度上，落到更低或更高的平台、跨过崖边时不会折；太阳很低时拉长的影子是最近邻重采样，清楚但有条纹。可以改成全世界一个影子层（CanvasGroup 里先合成覆盖度再统一乘），需要把影子节点从植物场景里拿出来，没做。
3. **夜里的灯笼**：乘法影子也会压暗灯笼照亮的地面（地形自己的影子只减主光）。现在靠夜里把影子强度降到约 0.5。
4. **大物体的排序**：一个点排序（树干在脚、树冠在南缘），走到大楠板根的侧后方时可能画错前后；地上的根永远在人下面。透视孔只对她。
5. **大楠够不到小屋**：地形把小屋放在离树干 15 米处，树冠半径约 11–12 米；在 3/4 俯视里树冠又画在树干上方，所以"小屋在树冠下"做不到。要么挪小屋，要么给大楠做一个向西伸得很长的主枝变体。这是地图布局的决定，留给主管/用户。
6. **只有夏末**：枫有绿、转红、红三种，其它没有季节变体，没有雪。
7. **尺寸与性能【未验证】**：64 株共 5.4 MB；大楠的树冠贴图 527 × 321、树干 412 × 429。树冠 shader 每像素最多约 14 次纹理采样（风动逆映射的 3 个候选位置各 2 次、法线、内壳、透视孔 3 次），影子 2 次；大树冠的重绘面积大。没在手机上测过帧率，软件渲染的数字不代表手机。
8. **烘焙的明暗只适合一个光向**：如果主光的屏幕方向改了（按约定不该改），反照率里的明暗不会跟着变。

## 8. 踩过的坑

1. 叶团最暗处画成最暗色，看起来像"泡泡纸/鱼鳞"：内壳要按叶团表面着色，只是略暗。
2. 叶簇太大、高光 1 像素：像干裂的泥。叶簇缩到 0.27 米，高光 2 像素，叶团之间不画缝。
3. 严格斜投影下树干被树冠正面挡住、注连绳是很深的 U：所以有 §2 的画面空间压缩。
4. 树冠底面全黑：最初投影和受光是同一个西北的太阳，朝向镜头的面全是背光。分开处理（后来主管把它定为全游戏的约定，15 号 §0）。
5. 根：先是爪子，后是"躺在地上的原木"（圆管一半在地面以上，有下切的暗面），压缩后又成了细棍。现在是轴线在土里的半埋隆起，横截面不压缩，从板根下面钻出来，末端潜入土里。
6. 影子往太阳那边伸：按树脚线性拉伸会把脚印后面的部分也往反方向拉。改成 fragment 里逐像素反查（只拉长朝外的一半），四边形按两种影子移动后的范围放大。
7. `TEXTURE` 不能当参数传给函数（16 号 §12.3）：影子 shader 里只能就地采样。
8. 投影用了地形当时的方位（西南偏西）以后，影子朝右上，违反 15 号规则；主管定下"受光与投影分开"之后改回西北。

## 9. 出处与许可
