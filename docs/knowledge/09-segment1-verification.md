# 第一段成品的验证教训（2026-10-14）

来源：第一段（标题、序章「送魂夜」、第一天早上）交付前，在桌面 1280×720、手机横屏 844×390、手机竖屏 390×844 三种视口上，用 `tools/playtest1.mjs` 走真实输入从标题打到「第一段　完」，逐张看截图。下面每一条都是这一轮真的发生过、并且只靠"看截图"才抓到的问题。

## 1. DOM 状态"已显示"不等于玩家看得见

- **标题菜单点不动。** 界面根节点 `.ui` 设了 `pointer-events: none`（为了让摇杆收到画布上的触摸），标题层继承了它。键盘能选，鼠标和触屏都点不动：手机玩家进不了游戏。机器人在桌面用 Enter，在手机上点了按钮但没有检查标题是否消失，所以前几轮都没发现。
  - 规则：浮层里凡是要接收点击的元素，自己写 `pointer-events: auto`；验证点击时，检查点击之后的结果（标题消失），不是检查点击发出去了。
- **淡入淡出层盖住了字。** `.st-fade` 是故事层最后一个子元素，叠在字幕卡和标题之上。序章高潮的「天岸」（白底黑字）和结尾的「第一段　完」（黑底白字）在 DOM 里都是"on"，画面上却被遮住了。
  - 规则：淡入淡出只盖画面和遮幅，永远不盖文字。在白屏或黑屏上出字的镜头，必须截图确认。

## 2. 测试时钟要和真实帧循环一样让出执行权

- 机器人原来在一个同步循环里一次推进上百帧，剧本里的 `await` 要等整个循环结束才继续执行，所以截到的是一些真实游玩时根本不会出现的状态（例如开场淡入之前的黑屏）。
- 现在每推进一帧都用 MessageChannel 让出一次执行权，和浏览器两帧之间的行为一致。

## 3. 3/4 俯视角的遮挡

- 角色约 2 米高（约 40 像素）。她正前方（北侧）2 米以内、贴地的物体，在屏幕上和她的头、斗笠处在同一高度，会被挡住。
- 第一天早上的梁（2.4 米长、横放）和压在下面的さぢ，在她"站到梁前面去抬"时整个被斗笠挡住，玩家看不到梁变轻的过程。
  - 处理：梁的把手放在西半段；"抬"的过场让她走到梁的西端、朝东。这样梁、它失去的重量和さぢ都在画面里。
  - 规则：可交互物如果横向很长，又是演出的重点，要让她站在侧面；先截图检查她站在默认位置时挡住了什么。

## 4. 竖屏：已取消（P-3）

- 这一轮曾给竖屏做过专门的竖幅远景、标题和对话框排版。用户随后决定取消竖屏："没什么意义，徒占资源，还容易出 bug"。
- 现在手机竖着拿时，只显示全屏提示「请把手机横过来」，游戏时钟和声音一起暂停（`src/app/rotate.js`）。竖屏专用的代码已经删掉，试玩也只跑桌面和手机横屏，`--mode=phone` 会先检查一次竖屏提示。
- 教训：新增一种设备形态之前，先问它值不值得长期维护。每多一种视口，每一次验证都要多跑一遍。

## 5. 字体

- CSS 里写的是 "Shippori Mincho"，页面实际加载的却是 "Shippori Mincho B1"。标题落下和字幕卡因此退回到 Noto Serif SC，和标题画面不是同一种字体。字体栈的第一项必须是页面真正加载的字族名。
