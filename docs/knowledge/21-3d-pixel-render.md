# 21 · 3D 场景按像素画渲染：渲染器契约与教训（美术样章）

日期：2026-10-14。适用：`godot/render3d/`（渲染器，本代理）、`godot/world3d/`（3D 世界与素材）、`tools/world3d/`（地形等生成器）、`tools/world3d_assets/`（树与道具生成器，素材代理）。用户的要求见 decision-log G5R-4、G5R-6。标【未验证】的没有实测；标【暂定】的会在美术样章定稿时再确认。

> **第 1–4 节是给素材代理的契约，先读。** 改契约只能改这份文件和 `godot/render3d/shaders/`，并在第 9 节记一笔。

## 0. 一句话

3D 场景、正交相机、固定朝北、俯角 55°；**Forward+ 渲染器（只做 Windows，2026-10-15 起）**；世界渲染进原生分辨率（640×360，跟窗口长大）的低分辨率视口，整数倍放大；相机按整像素对齐，余数平移放大后的画面。所有表面一个"屏幕像素格"（ptex）：程序纹理、风动都钉在这张格子上，所以画面不闪不爬。直立的物体向后倾（A Link Between Worlds 的做法），竖直方向和水平方向一样 1 米 = 30 像素；地形不倾，高差靠坡面明暗、光影和雾读出来。

## 1. 数字

| 项 | 值 | 说明 |
|---|---|---|
| 单位 | 1 = 1 米 | Godot 轴：X 东、Y 上、Z 南（朝向镜头） |
| 渲染器 | **Forward+** | 2026-10-15 起只做 Windows（decision-log G5R2-1 之后的主管决定）。SDFGI / VoxelGI / LightmapGI、体积雾、FogVolume、SSAO、SSIL、SSR 都能用，点光源没有每个物体 8 个的上限 |
| 原生分辨率 | **640×360**（720p ×2、1080p ×3、1440p ×4、4K ×6） | 与 2D 核心同一规则（knowledge/16 §13）：s = round(窗口高/360)，画布宽小于 400 时再减一，画布 = 窗口 / s。1366×768 → 683×384（×2），2560×1080 → 853×360（×3）。构图以 640×360 为准，宽屏多看两边 |
| 每米像素（PPM） | **30** | 相机画面平面上 1 米 = 30 原生像素（正交相机 `size = 视口高/30`，画面约 21×12 米）。主管定的数，可以在 28–32 之间调（改了要通知场景和人物代理） |
| 俯角 | **55°** | 相机看向北方、向下 55°；见第 8 节的取舍 |
| 后倾系数 k | tan(55°/2) = **0.5206** | 直立物体每升高 1 米向北移 k 米 |
| 地面的竖向压缩 | sin 55° = 0.819 | 地面上南北 1 米 = 24.6 像素 |
| 地形高差 | cos 55° = 0.574 | 地形升高 1 米 = 17.2 像素（地形不倾） |
| 直立物体 | 1 米 = **30 像素** | 后倾抵消了透视压缩：门 2 米 = 60 像素。人物（3D 模型，人物代理）：她连笠约 57 像素、脸约 20 像素 |
| 光 | 太阳沿连续的弧线走（第 5 节）；夜里月亮在左上 | 影子大多落在右下或下方，从不跳变（R-7） |

**一个直立物体上的点在屏幕上的位置**（素材代理离线预览、画屏幕空间贴图时用；原点 o 是物体的落地点）：

```
屏幕 x（右） = 30 · (x − o.x)
屏幕 y（上） = 30 · ((y − o.y) − sin55° · (z − o.z))
```

地形、水面、路、台阶、石垣这些"贴地"的东西不倾：屏幕 y = 30·(cos55°·y − sin55°·z)。（30 是 PPM；着色器里用全局 `w3_view.x`，不要写死。）

## 2. 素材怎么交（素材代理）

- **位置**：`godot/world3d/assets/<类>/<名>/<名>.tscn`，同目录放网格（`.res`/`.tres`/`.glb` 都行）和贴图。总目录 `godot/world3d/assets/catalog.json`（格式见 §2.4）。生成器在 `tools/world3d_assets/`，中间产物在 `tools/world3d_assets/out/`（已在 .gitignore）。
- **场景**：根节点 `Node3D`，**原点 = 落地点**（树根、房子地基中心、石灯笼底面中心），+Y 向上，正面朝南（+Z，朝镜头）。放置时整体可以绕 Y 转，但建筑的正面最好朝南或稍偏（东西两面在固定朝北的相机里几乎看不见）。
- **比例**：真实尺寸（米）。人物约 1.55 米、笠沿到 1.9–2.1 米；门高 1.8–2.1 米；民家 Q 版（宪章）：比真实小一圈，但门、檐要让她过得去。大楠例外：必须巨大（树冠罩住整片祠前空地）。
- **面数**（Windows、Forward+，2026-10-15 起；原来按手机定的上限作废）：没有硬上限，但要有理由：一个物体在 640×360 的画面上占多少像素，就配多少细节。参考：普通道具 ≤ 5k 三角形；建筑 ≤ 20k；树（干 + 叶片）≤ 20k，大楠 ≤ 60k。整个画面（含投影通道）目前约 30–60 万三角形；超过 150 万要先找渲染器代理。
- **阴影**：实体网格都投影（`cast_shadow` 默认开）；落在地上的薄片（落叶、草席）关掉投影。

### 2.1 材质：只用这几个着色器

全部是 `ShaderMaterial`，着色器在 `res://render3d/shaders/`。它们都 `#include "pixel_toon.gdshaderinc"`（全局参数、像素格、后倾、风、卡通光）。**不要用 StandardMaterial3D**：它不吃我们的光照、描边分类和雾。

| 着色器 | 描边类 | 用在 |
|---|---|---|
| `toon_solid.gdshader` | 1 实线描边（轮廓 + 折痕） | 木、石、屋、道具、树干 |
| `toon_solid_noline.gdshader` | 5 无描边 | 贴地的薄片、草席、远处的小东西 |
| `toon_solid_target.gdshader` | 4 目标（暖色亮边） | 运行时换上：当前选中的可交互物（渲染器负责切换，素材不用管） |
| `toon_foliage.gdshader` | 2 叶（只描外轮廓、较淡） | 树冠、灌木、竹叶、挂着的柿子 |
| `toon_foliage_target.gdshader` | 4 | 同上，选中时 |

描边类是模板缓冲（stencil）的参考值，由着色器文件固定；屏幕后期按类处理（第 6 节）。

**`toon_solid` 的参数**（都有默认值）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `tint` | 白 | 整体乘色 |
| `albedo_mode` | 0 | 0 只用顶点色；1 UV 贴图 × 顶点色；2 屏幕空间贴图（一个纹素正好一个像素，见 §2.3） |
| `albedo_tex` | 白 | 贴图（最近邻采样） |
| `screen_origin_px` | (0,0) | 模式 2：贴图里哪个像素（纹素角）对准物体原点 |
| `lean` | 1 | 1 直立物体（后倾）；0 贴地的东西（不倾） |
| `porosity` | 0.7 | 下雨变深的程度：土、木、茅草 1；瓦、金属 0.2 |
| `dither` | 1 | 明暗带边缘在像素格上抖动（人物和画出来的贴图用 0） |
| `vertex_ao` | 1 | 用 COLOR.a 当环境光遮蔽 |
| `emission_color`、`emission_energy` | 黑、0 | 自发光；**只有光源**（灯笼纸、火、鬼火）能大于 1，大于 1 才会泛光 |
| `emission_at_night` | 0 | 1：自发光乘以夜晚系数（白天不亮） |
| `cutaway` | false | 她走到后面时，挡住她的部分按像素格点状挖空（v1.4 起屋顶不用：被挡住的人物由渲染器画剪影，§6 第 15 条；大楠的干与大枝还用） |

**顶点数据**（`toon_solid`）：

| 通道 | 内容 |
|---|---|
| `VERTEX`、`NORMAL` | 真实（不倾）的位置与法线。光照用这个法线；**低面数的硬边法线更像像素画** |
| `COLOR.rgb` | 反照率（**sRGB**），每面或每顶点一个色；低饱和、自然色（§3） |
| `COLOR.a` | 烘焙的环境光遮蔽：1 开阔，0.5 缝里、檐下 |
| `UV` | 模式 1 的贴图坐标 |
| `UV2.x` | 表面花纹编号：0 素面、1 木板、2 树皮、3 茅草、4 石（朝上的面长苔）、5 瓦、6 和纸、7 朝上的面长苔 |
| `UV2.y` | 花纹强度（石和苔：苔的多少 0–1） |

花纹在着色器里按像素格逐像素算（`w3_pattern`），任何角度的面上都是"一个像素一个细节"，不会被拉伸、不会闪。

### 2.2 叶：卡片（推荐）或网格

`toon_foliage.gdshader`，`foliage_mode`：

- **1 卡片**（推荐，树冠、灌木、竹叶）：每张卡片四个顶点，着色器把它摆成正对镜头、纹素对像素的方片，所以叶子是清楚的像素画。每个顶点：
  - `CUSTOM0.xyz` = 卡片锚点（物体空间），`CUSTOM0.w` = 柔度 0–1（离干越远越软）。**CUSTOM0 要用 RGBA_FLOAT 格式**（`Mesh.ARRAY_CUSTOM_RGBA_FLOAT << Mesh.ARRAY_FORMAT_CUSTOM0_SHIFT`）。
  - `UV2` = 这个角相对锚点的偏移，**原生像素，整数**（x 向右、y 向上），例如 16×16 的卡片是 (−8,−8)、(8,−8)、(8,8)、(−8,8)。
  - `UV` = 这个角在叶片图集里的坐标。
  - `NORMAL` = 整张卡片的受光法线：从树冠中心球面化（`normalize(锚点 − 冠心)`，竖向略压扁），这样整个树冠像一团有体积的东西一块一块受光。
  - `COLOR.rgb` = 叶片图的乘色（sRGB），`COLOR.a` = AO（冠内侧暗、外侧亮）。
  - `VERTEX` 只用来算包围盒（写锚点 + 粗略的角就行），着色器会重建卡片。
  - 三角形顺序：**(0,2,1)、(0,3,2)**，角的顺序按上面 UV2 的例子（左下、右下、右上、左上）。这样在屏幕上是顺时针，Godot 当正面。（v1.1 写的 (0,1,2)/(0,2,3) 是逆时针、背面；`cull_disabled` 时引擎把背面的 NORMAL 翻过来，着色器虽然会再翻回去，但别依赖它。素材代理发现并改正，§9 v1.2。）
  - 阴影：在投影通道里卡片转向太阳，所以树冠投下带叶形的斑驳影子。
- **0 网格**：真的几何（松的枝盘、杉的层、苔团）。每个顶点后倾；`CUSTOM0.xyz` = 它所在摆动组的锚点，`CUSTOM0.w` = 柔度；`COLOR` 同上。

**叶片图**（`leaf_tex`）：RGB = 反照率（sRGB，2–4 个平的色阶，叶的形状清楚），A = 覆盖（< 0.5 剪掉）。**不要画固定方向的明暗**（受光由法线决定）。卡片大小 8–24 像素；同一棵树混用几种形状，边缘参差。

其它参数：`tint`、`lean`（1）、`wind_px`（柔度 1 时的最大摆幅，原生像素，1–2）、`porosity`（0.5）、`hi_band`（向阳的亮边带，1）、`cutaway`（默认开：她在树冠下时，挡住她的叶片点状挖空）、`cutaway_keep_px`（0；渲染器给大楠设 96：画面上比她高出这么多像素的叶子不挖）、`far`（遠化，0–1，见下）、`shade_fill`（0：大树冠背光面的补光，渲染器给大楠设 0.42）。

**无描边的叶**：`toon_foliage_noline.gdshader`（描边类 5）。蕨、薄、竹叶这类 1 像素宽的细叶用它，否则会被轮廓线吃成黑线（素材代理的发现，v1.2）。

**遠化（`far`，0–1）**：`toon_solid` 和 `toon_foliage` 都有。东西失去性质时，渲染器连续地把它调到 1：颜色抽饱和、提亮、略偏冷（向雾霭靠），明暗对比同时变平（太阳那一份 ×0.55，暗部补到 ×1.6）。不用再换"褪色网格"（素材代理做好的 `_far` 场景留作后备）。

### 2.3 贴图

- 尺寸 ≤ 256×256（叶片图集 ≤ 128×128），PNG，**最近邻**（着色器里已是 `filter_nearest`），无 mipmap。
- **导入设置必须是无损、不转 VRAM 压缩**：`.import` 里 `compress/mode=0`、`mipmaps/generate=false`、**`detect_3d/compress_to=0`**（Godot 默认在贴图第一次用于 3D 时把它重新导入成 VRAM 压缩，像素画会被毁掉）。生成器直接写好 `.import` 最稳。
- 纹素密度：UV 贴图（模式 1）按 **每米 20 纹素**画；朝上的面南北方向会被压到 0.82（可以接受）。
- 屏幕空间贴图（模式 2）：贴图就是这个物体在我们相机里的样子（按 §1 的公式投影），一个纹素一个像素；物体原点要对齐像素格（渲染器放置时会对齐）。适合需要手绘细节的主角道具（祠的正面、招牌）。

### 2.4 catalog.json

```json
{
  "version": 1,
  "assets": {
    "camphor_great": {
      "category": "tree",
      "scene": "res://world3d/assets/trees/camphor_great/camphor_great.tscn",
      "footprint": [[0.0, 0.0, 1.6]],
      "height": 22.0,
      "crown": {"centre": [0.0, 13.0, 0.0], "radius": 12.0},
      "tags": ["landmark", "climbable"],
      "anchors": {},
      "notes": "…"
    }
  }
}
```

- `footprint`：挡路的圆（物体空间 x、z、半径，米）。她和さぢ绕开它们。
- `tags`：`choppable`（能砍的树）、`pickup`（能拿起：树枝、柿子）、`interact`（祠、供物箱、柴堆）、`light`（灯笼）、`landmark`……
- `anchors`：命名的点（物体空间）：`light`（火口，渲染器在这里挂点光源）、`glint`（会闪的地方，例如供物箱里的钱）、`fruit`（柿子的位置列表）、`interact`（交互时她站的位置）。

## 3. 美术规则（来自宪章、P-2、knowledge/17、18）

- **调色**：低饱和的自然色。草地以 v0.1 为准：CIELAB 约 L\* 40、C\* 20、色相 125–140（knowledge/17 §3）；第一版烘焙的 C\* 36 就是被否的"荧光绿"。木偏灰褐，石偏青灰，茅草偏灰黄。暗部偏冷、亮部偏暖由光照负责，反照率不要自己画冷暖。
- **读取层级**：角色 > 可交互物与威胁 > 地面 > 植被。植被的明度范围比可交互物窄；可交互物在形状和色块上要比周围"干净"。
- **像素画质感**：大色块 + 少量像素级细节；不要逐像素噪声；树冠要成团、团与团之间留空隙；边缘参差。
- **不能有方块感**：不要轴对齐的方盒堆；石头、土堆、树根要不规则；建筑可以方（它本来就是方的），但檐、柱、墙脚要有手作的不齐。
- **重复**：同一种东西至少 3–5 个变体（形状、颜色、朝向）。
- **光源**：灯笼、火、鬼火才自发光；其它东西的亮是光照给的。

### 2.6 人物精灵图（精灵代理的图，渲染器负责摆）

- 俯角 T 的相机下，后倾的直立卡片要配 **精灵俯角 P = atan(sin T)**：T = 55° 时 P = 39.33°。精灵代理的工具可以按任何 P 出图（格子比 20° 版高 14 像素）：`bash tools/world3d/sync_sprites.sh 55` 会用它出图并放进 `godot/world3d/sprites/`（无损、不转 VRAM 压缩），`characters.json` 里记下 `_sprite_pitch_deg`。改俯角就要重出。
- 法线图在精灵相机的坐标里（x 右、y 上、z 朝观众）。世界法线 = (n.x, n.y·cosP + n.z·sinP, −n.y·sinP + n.z·cosP)，再转到本相机的视空间（`sprite_char.gdshader` 里做）。直接当 55° 的法线用，受光会偏 35°。
- 帧的位置用 `col` + 帧号（不只是 `row`）；每帧有 head、hand、foot 等锚点：渲染器用 head 锚点在笠檐下给脸一个亮度下限。
- 背着货走用 walk（约 2.4 米/秒），满速跑用 run。

## 4. 渲染器做什么（素材不用管）

- 放置：按 catalog 放进世界，原点落到地形高度，对齐像素格；按 `footprint` 让她绕开。
- 光：`anchors.light` 挂上引擎的点光源（OmniLight3D，连续衰减，进体积雾成光晕；第四轮），夜里亮；茅屋的 `anchors.light`（地炉）夜里在屋里亮，`anchors.smoke` 早晚冒炊烟。
- 风：全局 `w3_wind`；雨：`w3_wet`（材质按 `porosity` 变深）。
- 透视孔：一棵树（树干、枝、叶、注连绳）**一起**开同一个洞（第四轮，`sample.gd` `_tree_cutaway`：同一个半径、同一种散点边）；被树干、枝、屋檐、柱、墙挡住时画她的剪影（`XRay`）。
- 选中：把材质换成 `_target` 变体（暖色亮边）。
- 结界（第四轮）：`render3d/realm_mask.gd` 把 `zones.sanctum`、`zones.oku`、`zones.fog_*` 烘成一张 1 米一格的图；门口的雾是贴地的一缕一缕，她走到雾带最深处才涨满；画面的调色按她站的位置在结界内外之间过渡（`W3Env.set_realm`：两头放软、饱和度略升、暗部蓝绿、亮部暖，不加白）；浮尘、萩的花瓣在结界里更多。

## 5. 渲染管线（实现说明）

> **第四轮（2026-10-15）起光照全部换了**：Forward+；光是连续的（没有任何分档）；环境光是引擎的（半球天光 + VoxelGI + SSAO）；体积雾；HDR 视口 + 蓝噪声抖动。下面先写第四轮的做法（§5.4），后面的旧说明里"量化""档""EMISSION 放环境光"等只是历史。

### 5.5 第五轮：白天的颜色回到第三轮（G5R3-1），夜里保持第四轮

用户："色彩反而變得非常不自然不協調……全面 roll back 回前一版本"（第四轮的鲜绿、饱和的调色、蓝绿的阴影是"画蛇添足"），同时"夜裡的光非常好就按這個來"、"渲染器也不要退回"。所以**渲染器（Forward+、连续的光、HDR、VoxelGI、体积雾、灯）不动，白天的颜色按第三轮重现，夜里保持第四轮**，按 `w3_night` 混合（黄昏 18.4–19.6 时渐变）。具体：
- **时刻的关键帧**（`world_env.gd` `KEYS`）：6:24–17:24 是第三轮的原值（太阳色与强度、天光、地面反弹、雾色、lift / gain / 饱和度、分色）；0:00、4:24、5:24、18:24、19:36 是第四轮的（夜）。调色：第三轮的 S 曲线 0.32、分色按关键帧（夜里 ×1.6 / ×1.3）、不加曝光（夜里 ×1.25）；第四轮按色相转绿（`green_turn` 等）只在夜里。**结界不再有自己的调色**（软曲线、蓝绿暗部、暖高光都退掉）：结界和外面的区别交给内容（贴地的雾、浮尘、花）。
- **太阳的强度曲线**（`pixel_toon` 的 `w3_r3_ground` / `w3_r3_body`，`w3_sun_level`）：第三轮按档画太阳（地面 0.5 / 0.68 / 0.86 / 1，界在 n·l 0.04 / 0.30 / 0.58 / 0.80；其它 0.62 / 1，界在 0.06 / 0.42），对半侧着太阳的面很大方，低太阳也把地照得暖。现在保留这些亮度，但是一条平滑的曲线穿过每一档的中点（**不分档**，G5R2-1 仍然成立）；夜里月光用第四轮的包裹 Lambert。眺望的地（`v_sun_bands`）、替身（`vista_impostor`）同样。
- **画出来的阴影**（`w3_paint_shade`）：环境光看到的颜色 = 反照率的色相往冷的一侧转、彩度保留（`w3_shadow_hue`，第三轮的做法）× `w3_shade_tint`（第三轮的值：白天略冷，黄金时刻蓝紫）。天空只带两成颜色（`ambient_day_hue` 0.2：引擎的天光半球按亮度给，蓝天乘暖土会发灰，§6 #7）。夜里不转色相（第四轮）。引擎的天光给朝上的面只有天色的约四分之三到五分之四，所以白天乘 1.2（`ambient_day_gain`，见 §6 #34）。
- **叶子的贴图走第三轮的调色板**（`w3_ukiyo_tex`，叶片材质的 `ukiyo`，默认 1）：第一到第三轮叶片、旧精灵的贴图被转了两次 sRGB（§6 #20 的错），画面上比画的深、中间调更浓；第四轮修了错，颜色变浅变鲜。现在把那个结果当成调色板**有意地**做回来：贴图的 sRGB 值先过一次 sRGB 曲线再正常转线性。只用于第三轮就有的贴图；第四轮以后画的（按一次转换画的：大楠的新叶、furusugi、茅屋的卡片、篱笆的藤、菜园、地被）`ukiyo` = 0（`sample.gd` 的 `ONE_CONVERSION_LEAVES`，`grass.gd`），否则暗部发黑。夜里不用（`w3_ukiyo_tex` 按 `w3_night` 退掉）。
- **叶子的处理**（`toon_foliage_body`）：第三轮的：绿的彩度 ×0.8、鲜的黄绿在膝点 0.06 以上压缩；受光的一面彩度 ×0.72、亮度 ×0.88；正对太阳的一面亮一点暖一点（`hi_band`，连续）；逆光透光只留 0.35（夜里全）。
- **`lush`**（第四轮的鲜绿）白天不再生效（乘 `w3_night`）。
- **雨天不压平阴影里的细节**（`w3_flatten`，G5R3-5 "茅屋在雨天……全是色塊"）：第四轮的 `shade_flatten`（阴影里压掉一部分画出来的细节：大块明暗、细节在受光面）在有太阳时成立；雨天的光几乎全是天光，满画面都是"阴影"，于是所有表面成了平的色块。现在压平的份额乘 (1 − 0.85 × 雨量)（地形、实体、草场）。
- **草地只有一个颜色场**（`render3d/shaders/sward.gdshaderinc`，主管 2026-10-16）：要第三轮的草色，不要第三轮的斑。第三轮的宏观明暗按整级跳（fbm 7.5 米，点状接缝）、干草按阈值切（1–3 米一块、硬边），读出来就是用户说的"一块深一块浅"（G5R3-2）。现在干度（`w3_sward_dry`：m3.g 加 9 米的噪声，宽的 smoothstep）和宏观明暗（`w3_sward_tone`：10 米与 4.6 米两层，连续，通常 ±0.6 级）都是几米的渐变，颜色在调色板第 0、1 行之间、相邻两级之间插值（`w3_sward_col`）。地形（mat 0）和场景代理的草场（`world3d/grass_field.gdshader`）都从这里取色，草根就是脚下地面的颜色；草的光也和地面一字不差（`w3_sun_level`，地面曲线，wrap 0.15）。细节（单根深色草叶、地面字形、草尖亮一级）仍按整级叠在上面。**干草色回来了**（用户 G5R3-14 选 B："我需要把那種草地地面上的枯草黃色部分也加回來"）：干度图换回第三轮的公式（`tools/world3d/w3terrain/materials.py`，保留第四轮的"岩边土薄"和"结界里没有干草"），`dry_bias` 0（地形和草场），平草坪上又有稻草色的区域，边缘是几米的柔和过渡；整画面没有偏黄（12:30 绿色族色相 137，第三轮 131）。（先前写的"dry_bias 0.12、第五轮不找回"是 G5R3-14 之前的决定，已作废。）
- **树荫和绿篱影子里补回天光**（主管 2026-10-16：新布局里早、晚和大楠下的祠前比第三轮暗得多，L\* 中位 25–29 对 39；F1 东门、F3 磐座 10:00 树冠下一团深绿，石阶、路、磐座读不出）：第三轮的阴影一律照着整片天光（它没有 GI）；第四轮起 VoxelGI 在树冠下、绿篱边看到的天很少，太阳低时画面大半在这种影子里。现在 `light()` 在太阳被挡住的地方加回一份天光（`w3_shadow_fill(ATTENUATION)` = `w3_fill` × (1 − 阴影)，`w3_fill` = 当时的天光 × `shadow_fill` 0.55，`world_env.gd` 每帧写；夜里、雨里为 0）。开阔受光处一个像素都不变。量过：只在早晚补 0.8 时 07:36 L\* 中位 24.6 → 46.2、祠前 09:30 28.3 → 47.3、17:12 26.0 → 41.0（第三轮 39.1 / 39.4 / 39.8），12:30、21:30 逐像素不变；所以改成全天补、0.55。
- **光斑**（`w3_fleck`，场景代理和主管：原来的光斑是硬边的小点、只给 0.85 份太阳、不带天光，在碎石和路上读成一块块浅黄的"脏斑"）：现在是软边的圆斑（边上 1–2 像素过渡），图案按太阳方向上 11 米高处（树冠那一层）的点取，所以跟着树冠的位置、随枝叶晃；低太阳时顺着光拉长（太阳从叶隙里投下的像在地上是长的）；成簇的边也是软的；斑里是满的太阳，补回的天光照留（按真正的阴影算），所以颜色就是同一块地在开阔处受光的颜色。地面和草场用同一个函数。
- **验证**（`render3d/dev/asset_preview` 同一素材过两个渲染器：worktree 20e91e6 的第三轮渲染器、现在的渲染器）：杉 sugi_a 受光 / 半影 / 阴影 / 地上的影子 ΔE2000 ≤ 1.7（07:36、12:30）；枹栎 konara_a ≤ 3.8；平地（实体材质）≤ 2.6。场景里的差别主要来自素材和布局（新茅屋、新路面、地被卡片、东边的杉挡住了早晨的太阳），见 §7.0b。

### 5.4 第四轮的光（Forward+）

- **视口**：`use_hdr_2d = true`（浮点、线性）。`composite.gdshader` 自己转 sRGB、调色（Oklab 里按色相：橄榄色转向绿、黄色减一点彩度）、超过白的光按最亮的通道柔和压回（灯芯保持暖色、萤火保持黄绿），最后加 ±0.5 个码值的 64×64 蓝噪声抖动，噪声贴在世界的像素格上（`cam_cell`），相机整像素移动时它跟着世界走，不爬。眺望的视口同样（`vista_display.gdshader`，噪声贴在方向格上）。
- **直射光**：`w3_direct(n, l, col, atten, wrap)`：连续的包裹 Lambert（Godot 的灯光强度已经乘过 π，这里除回去），`w3_lit_tint` 只在受光面；叶子加 `w3_transmit`（逆光时透过叶子的黄绿光）。阴影图仍是硬边。
- **环境光**：引擎的。天空着色器 `ambient_sky.gdshader`（上半球是天色、下半球是地面反弹），白天乘 `ambient_day_gain`（1.5：影子约为受光面的一半亮，读成一大块，不是黑洞）；VoxelGI（256 细分、两次反弹，场景载入后第 2 帧烘，lavapipe 上 12–27 秒）在区域里取代天光，带遮挡和颜色反弹；SSAO（只影响环境光）。材质写 `ALBEDO`、`AO`，`AO_LIGHT_AFFECT = 0`。SDFGI 试过：正交相机 120 米外几乎无效、30 米处有色带，不用（`render3d/dev/gi_test.gd`）。
- **大块明暗 + 局部细节**（主管 12:55）：地形、实体材质给环境光的是"压平"的反照率（`shade_flatten`：地形 0.6，去掉颗粒和字形；实体 0.55，去掉 `w3_pattern` 的斑点、裂纹，贴图取 5 点均值），`light()` 里直射光乘 `v_detail = 细节反照率 / 压平反照率` 把细节放回去：影子里是整块颜色，太阳照到的地方才有细节。
- **画家的阴影色**：`w3_shade_tint` 只乘环境光（反照率乘它，`v_detail` 在直射光里再除掉）：白天蓝绿 (0.88, 0.98, 1.08)，黄金时刻蓝紫，夜里中性。VoxelGI 从暖土、茅草反弹的光不会把影子染成棕色。
- **树冠的影子成大块**：叶片卡片在投影通道里放大 35%（`shadow_shrink` 1.35）、不漏光（`shadow_sieve` 0）；地上的光斑由地形画（`v_fleck`）。
- **灯**：`render3d/lamps.gd` 给每盏灯建 OmniLight3D（平滑衰减 1.6、体积雾能量 1.4、不投影），没有环、没有档；眺望仍用 `w3_lamps` 数据贴图。
- **体积雾**：全局密度 0（俯视相机和地面之间的空气不是空气，全局雾会罩住一切），一个 FogVolume 盖住整个区域，`ground_fog.gdshader` 按"离地高度"给密度（地面最浓，`layer` 米衰减到 1/e，成团漂移），太阳透过树冠在里面成光束，灯在里面成光晕。**只在清晨浓**，白天几乎没有（空气要透亮，主管 16:00："雾只在远处、清晨和特定的地方出现"），夜里一层薄的给灯晕。雾的范围只到最远的地面（相机距离 + 45 米），切片 128 层（约 1.2 米一层：贴地不到 1 米的薄雾，2 米一层时经常被跳过）。
- **门的雾**（`realm_mask` 的 G、B 通道）：贴地的一缕一缕（离地约 0.8 米淡掉，两层噪声成条、随风流，带子边缘用噪声打散），受光侧暖、背光侧冷是散射自然给的。她走进雾带最深处（G > 0.62）时 `band_swell` 让雾涨到带子的高度、浓度 ×4（烂柯的换位置就在这几帧里）。**不要**做成罩在她身上的发亮方块（第一版的教训）。
- **结界里的调色**：**不加白、不抬黑、不加雾**（第一版这样做，整屏像蒙了一层奶，主管否了）。只放软色调曲线的两头（`composite` 的 `soft_ends`：暗部开一点、零仍是零；高光不爆），饱和度 +6%，暗部再偏蓝绿、亮部再偏暖。"仙境"靠光束、空气里的光点和花瓣、苔和花的颜色、更柔的阴影，不靠灰雾。

- **像素格（ptex）**：`w3_ptex(wp) = floor(20·(x, cos55·y − sin55·z))`。相机中心永远在整数格上，像素中心在 k + 0.5，所以每个屏幕像素正好对应一个格；世界里一个点的格不随相机变。程序纹理、抖动阈值都用格当种子：**不要用 FRAGCOORD 做抖动**（相机一动图案就爬）。
- **后倾**：顶点着色器里 `z −= k·(y − 物体原点 y)`，只在主通道做；投影通道用直立的几何，所以影子长度、方向是真的。光照用直立的法线。挂在空中的东西（灯笼挂在柱子的横杆上）原点也要按它离地的高度先后移 k·高度，不然会和挂它的东西错开。
- **卡通光**（`light()`）：太阳两档亮带（地形四档）+ 阴影（`ATTENUATION` 取 0.5 为界，硬边）；点光源按 4 档量化，抖动只在每档交界的窄缝里，而且是散点（不是有序抖动）；环境光放进 `EMISSION`（关掉引擎自己的环境光）。片元到光照函数用 varying 传反照率，`ALBEDO` 设为白。
- **画出来的暗部**（`w3_ambient` → `w3_shadow_hue`，v1.2）：暗部不是"反照率 × 蓝天"（暖色乘冷色会变成死灰：实测院子的土在树荫里是 (42,42,42)，C\* = 0）。现在：环境光只取亮度和五分之一的颜色；色相在 Oklab 里朝蓝紫转最多 0.38 弧度（暖色经红紫、绿色朝蓝绿），彩度保留 ×1.15，灰色加一点青灰。素净的颜色（土、石、木，Oklab 彩度 < 0.075）转得少，免得土在阴影里发红发重。
- **大树冠**：大楠的叶片在投影通道里放大到 1.3 倍、不漏光，树冠里还有一个只投影不显示的椭球（`_crown_proxy`），所以树荫是一整片，不是迷彩；树荫里的光斑由地形自己画（`v_fleck`：沿太阳方向往上 11 米去读树冠图，光斑落在投下的影子里，2–4 像素的小点，成簇，随风原地晃）。背光面有补光（`shade_fill`，树冠 0.42、树干 0.3），中午从南面看大楠不会变成一块黑盖子。
- **透视孔**只在主通道：投影通道里不挖（否则她周围的树荫会被挖出一个亮洞）。
- **全局参数**在 `project.godot` 的 `[shader_globals]`（`w3_*`），由 `render3d/world_env.gd` 每帧写。白天的天光（环境光）比 v1.1 亮 1.45 倍、太阳弱 8%：暗部约为亮部的 60%（L\* 约 27 对 40），不再是黑块。

## 6. 已验证 / 踩过的坑（2026-10-14，Godot 4.7.2，Mobile，lavapipe）

1. **Mobile 渲染器能做这条管线**：`hint_depth_texture`、`hint_screen_texture`、`light()` 自定义、fragment → light 的 varying、模板缓冲（`stencil_mode`；读模板的材质必须在透明通道）都实测可用。Mobile 没有法线缓冲，所以描边只用深度：轮廓 + 深度的二阶差找折痕，分类靠模板值。
2. **阴影粉刺（地形上的点阵）**，查了 Godot 4.7.2 的源码才弄清楚，三件事：
   - **正交相机下 `directional_shadow_max_distance` 不起作用**（`renderer_scene_cull.cpp`："its impractical ... in orthogonal camera"）：阴影图罩住相机 near..far 整个盒子的外接球。相机在焦点后 120 米、near 1、far 300 时，4096 的图铺在约 300 米上，一格 7.3 厘米，比一个像素还大。现在 near 60、far 190（`pixel_view3d.gd`；按高度图算过，所有可走的焦点下看得见的地面都在 100–157 米深，树最多再近 15 米），一格约 3.2 厘米。
   - **`shadow_bias` 要乘 `shadow_blur`**（`light_storage.cpp`：bias = shadow_bias / 100 × 深度范围 × blur × 质量半径）。我们要硬边，blur = 0，所以深度偏移一直是 0，调 `shadow_bias` 没有任何作用；只有 `normal_bias`（以阴影图的格为单位，再乘 1 − N·L）在起作用。现在 shadow_bias 写 0、normal_bias 2.0。
   - 就算这样，泉西南的坡上还有一片斜格子的暗点。根治：**地形在投影通道里沿法线往里缩 30 厘米**（`toon_terrain` 的 `vertex()`，`IN_SHADOW_PASS`）。地面永远不会自己挡自己，山脊、岩面投到地上的影子只移动不到一个像素。
   - 查法：`--noshadow`（点阵消失 = 是阴影图的问题），`--hide=` 逐个藏投影的东西，`--sbias=`、`--pancake=`、`--camrange=` 对照。
3. **有序抖动（Bayer）铺在缓慢变化的量上就是一片棋盘格**：明暗带交界、宏观色调交界、灯笼的光圈。都改成"只在交界的窄缝里抖、散点抖"（哈希 + 一点值噪声）。夜里灯笼的光圈原来是一大片网点，现在是干净的暖色圆斑，边缘是散点。
4. 3D 用到的贴图第一次被 3D 材质引用时，Godot 会把它的导入设置改成 VRAM 压缩（`detect_3d`）。人物精灵图属于精灵代理，我们不改它们的 `.import`：渲染器把它读成 Image 再建 `ImageTexture` 给 3D 用。
5. `pkill -f <字符串>` 会把自己所在的 shell 也杀掉（命令行里有同样的字符串）。按可执行文件的路径找 PID 再杀。
6. **透视孔不能进投影通道**（见 §5）；**`include` 里的函数不能有和材质 uniform 同名的局部变量**（`tint`：编译成功但取到了 uniform，报 vec3 × vec4）；**`fragment()` 里不能 `return`**。
7. **冷色乘暖色 = 灰**（§5 画出来的暗部）。**石头的调色板不能偏蓝**：45° 以上的坡在 3/4 视角里是一条蓝灰色的带子，第一眼读成河。石头改成暖灰（L\* 38、C\* 7、色相 68），阴影把它转成灰紫。
8. **路线机器人要会"贴墙加侧键"**：只按一个方向键顶着一个圆形障碍会卡死（滑动只沿坐标轴）。现在停住 0.3 秒就加上朝目标一侧的键（玩家也会这么做）。岩石的挡路半径按"出土的粗细"算（埋得深的岩石大半在脚下），不然眺望岩被自己的岩石围死。
9. **大的道具会吃掉布局**：素材的茅屋比布局预想的大（屋顶 7.3×5.7 米），柴堆原来的位置正好卡在茅屋和院子东墙之间，她过不去。标记跟着素材改了（§11）。
10. **量化过渡一律用散点**：明暗带、宏观色调、雾、水深、灯光圈、AO 的每一档交界都是"整档 + 窄缝里散点"（哈希约 0.65–0.7 + 值噪声约 0.3–0.35，缝宽约 ±0.15 档），种子是像素格。第三轮起眺望的转场也不用有序抖动了（雾白淡入淡出），整个渲染器里不再有有序网点。
11. **几何预算会悄悄爆掉**：石垣的每块石头原来细分 3 级（1,280 个三角形），整个院子的画面有 188 万个图元；石头改成细分 1 级（80 个三角形）后是 30 万，看不出差别。像素画面里，一块石头在屏幕上不过十几个像素，细分超过 1 级都是浪费。用 `godot/render3d/dev/count_tris.gd` 数素材的三角形，用 `--perf` 看整个画面。
12. **Movie Maker 的帧尺寸是 `project.godot` 的 window_*_override（1280×720），不是窗口**（`main.cpp`）；窗口不一样大时，它把窗口的图用**双线性**缩到这个尺寸（`movie_writer.cpp`）。1920×1080 的窗口录出来是 1280×720、像素被抹糊的帧（一列 2 像素一列 1 像素地交替）。`tools/world3d/record.sh` 用一个"项目视图"录：`tools/world3d/out/proj_WxH/` 里只有改了 override 的 `project.godot`，其余全是指回 `godot/` 的符号链接，窗口与帧同尺寸，每个原生像素是正好 4×4 的方块（查法：相邻列差 ≤ 2 的连续段长度全是 4）。
13. **画出来的暗部在黄色上有一道断崖**（第二轮）：`w3_shadow_hue` 把色相往蓝紫（Oklab −95°）转，转向取最短的一边；黄色（约 85°）正好在对面，差一点点就转向相反的两边。新茅屋切面的颜色只改亮一点，阴面就从锈红跳成了青柠。在对面附近把转角淡出（±32° 内渐弱，±5° 内为 0）。查法：`tools/world3d/metrics/shadehue.py` 模拟某个 sRGB 反照率的阴面颜色。
14. **Mobile 每个物体最多 8 个点光源**，墓前十盏灯只能挂 3 个光源，读不出"一盏一盏"。灯改由渲染器自己算（v1.4）：灯的位置、颜色、范围写进一张 64×2 的浮点数据贴图（全局 `w3_lamps`），每个材质在 `fragment()` 里遍历亮着的灯，按最亮的那盏取光（不相加），4 档量化、最外一档贴近环境亮度。验收的量法（`tools/world3d/metrics/night.py`）：同一帧"灭灯"版本相减，看灯加的 L\* 分布、跨最外一条缝的 L\* 差（院子中位数 1.7、墓地 2.1，要求 ≤ 4）、灯外的明暗层次。
15. **人物被挡住时画剪影，不挖洞**（第二轮）：`sprite_xray.gdshader` 不做深度测试，模板"不等于 3"（她自己画到的地方是 3）的地方才画；脚边 9 像素内要求遮挡物在 0.6 米以外，否则她走进草里，脚下会一直套着一圈轮廓。茅屋屋顶原来的透视孔在她站到屋后时只露出屋里的地板，现在关掉了。
16. **大楠的树冠从南面永远在画面上方之外**：素材的南面是"高拱"（让树干和注连绳露出来），俯视相机下，南面任何位置都看不到一片树冠的叶子（关掉透视孔实测）；绕到东、北、西面，4–10 米高的大枝横贯整个画面，树冠围着她。所以样章的路线绕树一圈，透视孔缩小（5.0 → 3.8，她周围约 95 像素的一圈"林中空地"），画面上缘留一圈枝叶（`cutaway_keep_px` 96）。
17. **茅草的台阶方向弄反过**：台阶如果是"上一层往里缩"，切面朝北（朝屋脊），正交相机从南边看不见。台阶是"上一层压在下一层上、下缘修齐"，切面朝下坡、朝镜头。
18. **透视相机转头会闪**（第三轮，眺望）：透视投影转动时只有屏幕中心的内容按整像素平移，两边按 1/cos² 多走零点几个像素，俯仰也让每一行的速度不同，所以每帧都重新取样，散点和草丛像沙子一样闪（屏幕中间三分之一就有 7–17% 的像素在相邻两帧对不上）。眺望改用等距圆柱投影（§10）：转头 = 整幅画面整像素平移。另外两个坑：在 SubViewport 里自己写 `POSITION` 时，y 要乘 `sign(PROJECTION_MATRIX[1][1])`（渲染到纹理时投影是上下翻的）；`VIEWPORT_SIZE` 在顶点阶段读出来是 0，像素尺寸要用 uniform 传。还有：后处理材质如果在相机位置算出来之前就建好了，它的 `eye` 一直是 0（只在 eye 变化时才写），地面标记全部找不到地：现在每帧把 eye 写给所有眺望材质。
19. **远处的一条白带很容易读成水**（第三轮，眺望的遠化）：在地平线附近、平的、亮的一条带子，只要①上面有零星的亮点（水田和河映着天：暗底上的亮点就是水面的反光）、②远端是一条等高线（白只到一个固定高度：像湖岸）、③边是断开的亮点（像浪花），就读成海或湖，黄昏时更像。改法见 §10：白里水不映天、暗的东西留淡墨（暗点在白底上，不要亮点在暗底上）、白往上爬的高度随地方起伏、亮边在屏幕空间里按"白挨着同一片地上的有色的地"画，连续不断。把整个远处（连远山）都变白也试过：远山成了一片平的米色剪影，地平线和纵深都没了，大面积平涂，不用。

20. **贴图被转了两次 sRGB→线性**（第四轮发现，从第一轮起就有）：采样器带 `source_color` 时 Godot 已经返回线性值（实测：0.5 的灰带 `source_color` 输出 128，不带输出 188；`render3d/dev/srgb_test.gd`），`toon_foliage`、`sprite_char`、`sprite_xray` 又调了一次 `w3_srgb_to_linear()`。叶片、地被、人物在画面上比画的暗 3–10 倍、彩度偏高；场景代理量到的"草地彩度翻倍"、大楠下一团团黑绿就是它。规则：**带 `source_color` 就不要再手动转；手动转就去掉 `source_color`**。
21. **正交俯视下 SDFGI 没用**：120 米外的级联太粗，看不出反弹；拉到 30 米能看到但有色带。用 VoxelGI（烘一次，光照随时间实时注入）。全局体积雾密度必须是 0（见 §5.4）。
22. **新的 `class_name` 要先导入一次**（`godot --headless --path godot --import`），否则直接跑场景时报"找不到类型"并卡在解析错误上；`floor()` 返回 Variant，`var x := 1.0 + floor(...)` 推断不出类型，用 `floorf()`。脚本改完先 `--check-only --script res://...` 查一遍，比跑一次截图快得多。
23. **"降对比"不等于"加白"**（第四轮，主管否掉的第一版结界调色）：抬黑位、整屏加白、加雾，画面就蒙上一层奶，绿发灰。要柔和：只放软色调曲线的两头（零仍是零），饱和度保住或略升，暗部偏蓝绿、亮部偏暖；空气要透亮，雾只在清晨、低处和特定的地方。
24. **噪声打散边缘时要乘回原来的遮罩**：门的雾用"带子的值 + 噪声"过阈值来打散边缘，没乘带子本身的羽化范围，结果整张地图上噪声高的地方都冒出一团团白雾。`edge × smoothstep(0, 0.18, 带子)`。
25. **竖起来的光带从上面看是一团白斑**：光束的条带沿太阳方向立起，正午太阳高时几乎竖直，俯视下缩成一团发白的圆斑（像雾、像脏）。太阳高于约 45° 时让它们淡出，光束留给早晚和体积雾。
26. **体积雾的切片要够细**：正交俯视下切片沿视线排，原来 96 片铺在 200 米上（约 2 米一片），贴地不到 1 米的薄雾经常落在两片之间、被跳过。雾的范围只到最远的地面（相机距离 + 45 米），切片 128。
27. **真实输入检查在每秒一帧时会"丢键"**：按下和松开落在同一帧里，游戏两次都读到"没按"。全开的画面在 lavapipe 上约每秒一帧（阴影图那一遍就占三分之二），所以检查时关掉 GI、体积雾、SSAO 和太阳阴影（约每秒 4 帧），眺望里转头改成"按住直到游戏日志里出现目标朝向"（`input_check.sh` 的 `hold_until`）。输入的路径（XTEST → X → Godot → 游戏）不变。
28. **每秒 30 帧以上时她会卡在圆形挡路的边上**（第四轮）：walker 原来只试"整步、只走 x、只走 z"三种，一步只要擦到一个圆就整步作废；lavapipe 上每秒 4 帧时一步 0.6 米，跨过去了，录像（固定 30 帧，一步 8 厘米）和真机上就卡死在一棵树的边上。改成先沿圆的法线把这一步推出圆外（沿边滑过去），推出的距离超过一步才退回三种试法（`walker.gd` `_slide`）。查法：`GODOT_EXTRA="--fixed-fps 30"` 跑路线，卡住两秒会打印挡住她的圆。
29. **抬起来的高度场云读成岩石**（第四轮第二次，主管）：一张网格按云场抬起、每个像素重算法线的雲海，近看是一块块不透明的白团：下沿是网格掉进缝里切出来的硬线，里面是平的白，几何是一个个半球，像积雪的石头堆。云要读成云，靠的是：大块的明暗（法线一大半取整团云的、只一小半取每个云团自己的）、底下带蓝灰的阴影、边一点点变薄（上沿脆一点，下面和底部散进空气里，用有序抖动在方向格子上过渡）、云与云之间有缝。现在的做法是**一团云 = 一堆朝向相机的云团卡片**（§10 雲海），每团按"球面法线 × 整团云的椭球法线"打光；比高度场还省（lavapipe 上眺望一帧 250–320 → 150–175 毫秒）。
30. **透明卡片要自己排先后**：MultiMesh 的实例按数组顺序画，不按距离排；云团卡片不写深度（写了描边通道会把云当地面描），所以近的云团必须后画。CPU 上按云团离眼睛的距离排一次（云团内的卡片在搭的时候排好），云随风漂，每 8 秒或眼睛换地方时重排。
31. **远处粗网格上按地图坐标取的纹理会拉成"帘子"**（第四轮第二次）：眺望的地网格到了两公里外，圈与圈相隔六七十米，向着她的坡在屏幕上是又窄又高的三角形，按 xz 取的林子、草的噪声在一个三角形里几乎不变，整面坡变成一道道竖条，像挂着的布帘（云薄了以后才露出来）。改成三维的噪声（xz 和高度一起，`vista_ground` 的 `vnoise3`），并且远处的法线和高度按像素从高度图重算。只按像素重算法线没有用（查法：`--vdebug=albedo` 看反照率本身就是竖条）。
32. **人物的"后仰"和"整像素对齐"是俯视相机专用的**：`char_common` 的 `c3_lean_snap` 把她的竖向拉长、脚对齐俯视的像素格；别的相机（眺望的正交相机）看她时要关掉：实例 uniform `c3_no_lean = 1`（默认 0，世界里不受影响）。不能在节点上加一个反向的剪切来抵消：弹簧骨骼在全局空间里往下垂，抵消以后头发会往南斜 27°。
33. **`render3d/dev/asset_preview` 的图从第四轮起是线性的（太暗）**：3D 视口改成 HDR 以后，它直接把视口存成 PNG，存的是线性浮点、没有调色：同一块地 PNG 上 L\* 40，游戏里 L\* 73。第五轮改成存窗口里调过色的画面（和样章的 `--shots` 一样，按整数倍取原生像素）。比颜色只能用调过色的图。
34. **引擎的天光比"天色"暗**：环境光来自 `ambient_sky.gdshader` 的半球，引擎按它的辐射图（32 像素、滤过）给漫反射的环境光；朝上的平地实际拿到的约是天色的 3/4–4/5（第三轮在着色器里直接用天色的亮度）。同一素材过两个渲染器比：白天乘 1.2 时影子和第三轮差 ΔE ≤ 4。
35. **`pkill -f` 和 `pgrep -f | kill` 都会杀掉自己**（第 5 条的又一次）：命令行里含有要找的字符串时，自己的 shell 也匹配。只杀可执行文件是 Godot 的：`readlink /proc/$p/exe` 等于 Godot 的路径才杀（scratchpad `bin/killgodot.sh`）。
36. **VoxelGI 会把 MultiMesh 的每个实例按它的变换画进体素**（`VoxelGI::_find_meshes` 对 `MultiMeshInstance3D` 取 `get_meshes()`）。实例在着色器里才摆开的（草场：变换都是单位矩阵，顶点着色器按 `INSTANCE_ID` 铺满 16 米区块），烘焙时 2500 个小片全叠在区块角上：GI 里多出错的亮/暗块，烘焙也白白变长。这类节点要 `gi_mode = GI_MODE_DISABLED`（`grass.gd` 已设）。
37. **手柄在容器里没法走操作系统那一路验证**：没有 `/dev/uinput`，Xvfb 也不发手柄事件。能做的是把 `InputEventJoypadMotion` / `InputEventJoypadButton` 交给 `Input.parse_input_event`（设备 0），走 Godot 自己的输入那一段（`render3d/dev/shell_check.gd`）；`Input.get_connected_joypads()` 这时是空的，所以读手柄的代码在没有连接的手柄时也读 0 号。真手柄要在 Windows 上再验一次。

## 8. 俯角怎么选

- 越高（60°）：地面压缩少（0.87）、朝北的坡显示得更全（35° 的北坡还剩 60%），但地形高差更扁（1 米 = 10 像素）。
- 越低（50°）：高差更明显（12.9 像素/米），朝北的坡压得更狠（35° 北坡只剩 41%）。
- 直立物体后倾以后，不管俯角多少都是 20 像素/米，所以素材的样子基本不受俯角影响。
- 对照图：同一位置 50/55/60（`--pitch=`，院子与泉）。
- **结论：保持 55°。** 对照图里三者差得不多：地面的南北方向，50° 是 55° 的 94%，60° 是 106%（sin 之比）。50° 时泉池和院子更扁，朝北的坡更窄（35° 的北坡只剩 41%）；60° 时地面更开，但岩面、岸、石垣的高差更扁（1 米只有 10 像素），茅屋的屋顶在画面里更大。55° 取中间。另外精灵图是按 55° 出的（§2.6，P = 39.33°），改俯角要重出精灵图；对照图里 50° 与 60° 的人物用的还是 55° 的图。

## 10. 眺望（W3Vista，`godot/world3d/vista3d.gd`）

> 第三轮（2026-10-15）重做到成品，回到样章里：她在眺望岩上站定，画面经过雾白进入眺望。下面是现在的实现；第一轮的做法（剪影树、平面雾海、按像素溶解）已经全部换掉。

**她怎么看**：在眺望岩上站定（离标记 1.9 米以内，没按方向键、几乎不动）0.8 秒，画面 0.3 秒淡进雾白、0.35 秒淡出成眺望（`vista_display.gdshader`：白色是这个时刻的雾色偏白，不用网点）。A/D 转头；转到范围的尽头再按住 0.35 秒，经过雾白转身到另一处；W/S 回到俯视（同样经过雾白）。两处：

| | 朝向范围 | 相机 | 俯仰 |
|---|---|---|---|
| 向外（南） | 95°–292°：东边炭窑的烟 → 南边的平原 → 西边峡谷里瀑布的水雾 | 她身后北偏西 12.5°、高 28°，距离 = 每弧度像素 / 20（270 像素高时 18.55 米）：她的精灵一像素 = 屏幕一像素 | 南 −13°、东 −6°、西 −2°（按朝向插值：朝南时她的脚在画面里，东西抬起看烟和水雾） |
| 回望（北） | −12°–60° | 她南面 18 米、离她脚 4 米高，悬在落差上方 | +4°：大楠高出鞍部的山脊线，罩着茅屋和祠 |

**投影是等距圆柱（equirectangular），不是透视**（`vista_common` 的 `v_project`）：屏幕上一个像素就是方位角固定的一步、仰角固定的一步（每弧度 371 像素，270 像素高时），所以她转头（偏航和俯仰都按整像素走）时**整幅画面按整像素平移，每个像素都不变**，只是挪了位置。透视相机转头时只有屏幕中心是整像素平移，两边按 1/cos² 滑动零点几个像素，每一粒纹理都重新取样：第一版量出来转头时屏幕中间三分之一有 7–17% 的像素在相邻两帧之间对不上（闪），换成等距圆柱以后，转 3 个像素的两张图除了会动的东西（烟、云的漂移）全部对得上（差 0.3–0.7%）。世界里的竖线仍然竖直、地平线仍然是平的，在 74°×42° 的视野里别的线弯得很少。做法：每个着色器自己写 `POSITION`（方位角、仰角 → 像素 → NDC；深度用到眼睛的距离，按相机投影矩阵的 z 行写进深度缓冲，所以描边照样从深度读距离）；她身后的顶点直接裁掉（不然跨过身后接缝的三角形会横跨整个画面）；精灵、替身卡片、房子、构件在像素空间里搭；天空在天空着色器里按 `SCREEN_UV` 反算方向；Camera3D 只给光照提供视空间、负责剔除（视野放宽 20°，免得边上的东西被剔掉）。相机在一处里只转不移：替身卡片的帧、地面标记的锚点、明暗交界的散点种子（`v_dir_cell`：方向格子 = 屏幕像素 + 偏航/俯仰的整像素数）全都钉在世界上。

- **声音**：她朝那边看时环境声变小变闷，转回来恢复：`far_share()` 沿画面横向 7 条、地平线下 0.5° 和 2.5° 两条射线走到地面，取落点的 k 的平均；`Audio.far(k)`：环境声总线最多 −14 dB、低通从 20 kHz 降到 1.1 kHz，约 1 秒过渡；日志 `AUDIO far=…`。（第五轮前半这里按画面的俯角取样，射线全落在脚下的坡上，k 一直是 0；已修。）

**褪版（第五轮前半试过，G5R3-22 否了）**：把遠化画成一张木版画的色版一块一块没印上（前沿外先掉晕染、再掉绿、蓝、土，只剩墨线和空摺；纸、墨、版色都从调色板取）。否的原因（用户原话的意思）：①**位置不对**：画在远山那一边，和序章里"潮从平原中心的町爆开"对不上；②**看起来脏、像灰模**：灰褐的纸、满是又黑又碎的短线，像潦草的铅笔速写贴在柔和的平原上。技术上的教训：掠射角下连续的坡，相邻像素行的深度差也超过距离的几个百分点，按深度跳变描边会把它当成边（一条条黑带、满地短横线）；要描真正的遮挡边，得看二阶差分（一侧的跳变远大于另一侧），线密的地方用"窗口里的墨像素数"去碎会互相撑腰、去不掉。

**遠化与空气**（第四轮第二次，主管："远处那条米色的宽带读起来像沙滩，改成大气透视"）：前缘以外不再是一片平的纸白、也没有亮边了。现在遠化就是"比它的距离更远"：`v_drain` 在前缘以内仍是 0.02–0.18，过了前缘在之后三分之一个半径里连续升到 1（高地保留得多：远山一层一层高出低地的霭）；`v_air` 先把颜色抽掉一些（保留明度），再按空气的量 `1 − (1 − 霭)(1 − 0.68 × 遠化)` 混向这条视线上**天的地平线颜色**（`v_haze`：朝太阳一侧暖、背着太阳的一侧偏冷，黄昏是玫瑰色和淡紫，太阳周围有它的光晕，和 `vista_sky` 一样；夜里城市上空的霭发暖）；太阳的那一份按同样的量减掉（`v_air_keep`）。地的起伏和画（林子、田、河、村）都还在，只是越来越淡、越来越蓝灰；山脊在远处画一道很淡的深线（`vista_post`），一层层的山因此分得开。霭是连续的，不分档（HDR + 显示端的蓝噪声抖动不出色带）。夜里过了前缘的村子不亮灯。下面这段是第三轮的做法，留作记录：

**遠化**（第三条，`vista_common.gdshaderinc` 的 `v_drain`、`v_air`、`v_paper`，边在 `vista_post`）：和云是两种东西，也不能像水或冰。遠化之环（区边的椭圆）以外，地越远越淡、越灰（失去"近"）；过了**前缘**（以区中心为圆心约 5 公里、半径随方位起伏 0.62–1.42 倍）地变成一片平的纸白：没有明暗，只留地的"画"，像晒褪色的印刷品：**暗的东西留一点暖灰的墨**（林子、村边的树林、屋顶、高架桥、河是一条淡线，按地的环境光亮度 ÷ 天光算，所以一天里都成立），亮的东西就是纸；山脊和轮廓是一道淡的暖灰线。前缘以外这片白往上爬到的高度**随地方起伏**（−250 到 +350 米，2.5 公里一个起伏）：有的坡爬上去、有的停在山脚，远山的山头仍然高出它。白和保留颜色的地相接的地方（前缘、白的上沿），`vista_post` 在屏幕空间里画一道 1 像素的亮边（白的一侧；只在同一片地上，前面挡着的东西不算），所以边是连续的，翻过坡也连着。白色是暖的纸白，压在世界调色的削顶以下（约 0.85 sRGB：再亮墨和亮边就看不见了），夜里是暗的淡紫的微光，黄昏带一点暖、不跟着天变橙。
  - 三个读成"水"的原因（第三轮里改掉的，§6 第 19 条）：①残影里亮的是水田和河（它们映着天），成了暗底上的亮点，像水面的反光；②白只到一个固定高度（高处保留自己），远端的边是一条等高线，像湖岸；③亮边是在地面上按距离画的，地起伏时断成一串亮点，像浪花。现在：水在白里不映天（水田是纸，河是一条淡墨线）、白的上沿随地方起伏、亮边在屏幕空间里画。冷白挨着雾霭也像湖，所以是暖白。

**四个方向的远处好奇点**（第四条，map v3 草案 §2）：为了这个改了远景的地理（远景不是可走的地；布局是待审的提案）：

**她和さぢ**（第九条）：さぢ仍是背影帧的卡片，精灵一像素 = 屏幕一像素；人物保护：亮度下限（自己颜色的 42%）、太阳那一侧的轮廓亮边、不抖动。**她是 3D 模型**（第四轮第二次，主管问眺望里是不是新模型：之前还是旧精灵）：`_build_fig3d` 在一个自己的小世界（40×52 像素的 SubViewport）里放一个 `Character3D`，正交相机从眺望的眼睛方向看她，20 像素/米（和眺望的比例一样），她的脚落在画面的固定像素上；这张画当精灵帧用（`vista_figure` 的 `baked`：已经受过光，只补一圈 1 像素的描边，取旁边颜色的深色，再加空气）。关掉俯视用的后仰和对齐（§6 #32），太阳照抄世界的，另有一盏从相机一侧来的补光（人物保护的正面补光：眺望朝南，她的背一整天在阴影里）。她跟着视线转身，但离背对相机最多 55°（脸上的五官是俯视相机专用的像素印章，别的相机看不对）。只在眺望显示时更新和渲染。

## 11. 地形与布局（`tools/world3d/`）

- 一条命令：`python3 tools/world3d/build_terrain.py`（约 45 秒，含眺望用的外围地形和 Godot 导入）。中间产物在 `tools/world3d/out/`。
- **视线**（placement.py `clear_view`）：3/4 视角里一棵高 H 的树会挡住它北面约 1.2·H 米的地面。院子、祠前、墓地、道祖神、眺望岩、泉的南面都不种高树；框它们用两侧的树（三角构图），不用正前方的树。
- **冠下的落叶**不是圆盘：每棵树的冠影轮廓是分瓣的（3、5、2 瓣）再加 1.4 米尺度的噪声磨边。
- **土只在脚磨出来的地方**：路、院子、檐下。土的调色板 L\* 43、C\* 8、色相 78（夯实的土，安静）；石头 L\* 38、C\* 7、色相 68；岩石只在 41–50° 以上，或山脊的基岩成片露出的地方。
- **标记**：茅屋在 `hut`，门（素材的 `anchors.door`）在 `hut_door`；柴堆在院子西边；放标记道具的代码在 `sample.gd _place_marker_props()`（茅屋、祠、供物箱、九座无缘墓 + 十盏挂在钩上的提灯、道祖神、柴堆、落枝、斧头树桩、筧、路标、道标、竹篱、篮子、草垛；石灯笼与院子里的提灯由 `dressing.gd` 交出位置）。有 `lit` 变体的灯在黄昏到黎明换成亮的（时间流动时一盏一盏错开 0.18 秒点亮，光圈各自 1.2 秒淡入），光由渲染器的灯负责（§9 v1.4：墓前十盏灯每盏一个光圈）。
- **竹林**（第二轮减密）：泊松采样之后再筛一遍，丛与丛至少 2.8 米，低频噪声开出林间空地（224 → 72 丛）；筛在随机数抽完之后做，所以其它所有 placement 一个不变。

- **中档独显的估计**（GTX 1660 / RTX 3060 一级，未实测）：每帧 4–8 毫秒，远超 60 帧。理由：原生只有 640×360（23 万像素），逐像素的开销（光照、5 张描边方片、调色）很小；70 万三角形、255 次绘制对独显是零头（投影通道 4096² 的阴影图约 1 毫秒）；VoxelGI 在 640×360 上做锥形追踪约 0.5 毫秒，每帧把光注入体素约 1–2 毫秒；体积雾 128×72×96 个体素约 0.5–1 毫秒；SSAO 半分辨率约 0.2 毫秒。CPU 一侧每帧的脚本（人物、粒子、透视孔、结界）约 1 毫秒。lavapipe 和独显的速度差一般是 100–300 倍，1.8 秒 / 200 ≈ 9 毫秒，和上面逐项的估计同一个数量级。
